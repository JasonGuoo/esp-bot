## 本轮针对真实硬件与恢复行为的修改

- S31 PSRAM 改为有效的 200 MHz 选项，并使用公开的 `SPIRAM_XIP_FROM_PSRAM` 开关；删除无效的 80 MHz 设置。
- 启用 SC101IOT 官方驱动和 VGA 模式。视觉适配接受 UYVY/YUYV，保留由 ESP-DL 完成的颜色处理；180° 旋转按共享色度的双像素组处理。
- 保持硬件欠压检测 / 复位开启，记录复位原因。正常行为不改写应用分区，不在掉电时临时尝试保存数据。
- 启用 SDK `NVS_FLASH_VERIFY_ERASE`，不完整的 NVS 擦除会回读校验并最多尝试两次。该开关用于配置写入遇到供电不稳的恢复；不是任意电气故障免损坏的保证，也没有执行擦除中断电故障注入。
- 外观通过 NVS 单键提交；相同值不重复写入，NVS 故障不自动擦除。
- 每次启动从构建时 Wi-Fi 配置恢复连接；未指定时尝试已有的驱动 NVS 配置。重连使用 RAM，不因每次开机 / 掉线重写 Wi-Fi 配置。
- 本次 Wi-Fi 通过 Mac 本地输入框提供，保存到被 Git 忽略的本机配置，没有打印密码。
- `ESPBOT_SERVER_ID` 选择这台 Mac 的稳定公开服务器 ID。重启或断连后重新发现地址和端口；没有目标时继续重试，不自动选择其他 ID。
- 保留本地运行时独立于网络；诊断 LAN 不开放音频、图像或远程行为权限。

## 首轮实测发现的问题与修正

- AFE 的原四帧缓冲会停在四帧；八帧复测也停在八帧。官方引擎保留的起始历史实际上是 `vad_min_speech_ms + vad_delay_ms`，当前合计 256 ms（八个 32 ms 块），还需要额外空间接收新块。最终取消项目的容量缩减，使用官方默认 50 帧后持续计数通过。单个采集 worker 顺序拥有官方 reset/feed/fetch；feed 返回零时仍尝试有界 fetch。
- ES8389 1.5.11 的 `set_mute` 实际写入 ADC 静音位。原先输出静音导致麦克风采样全零；正常运行改为关闭 PA GPIO 7 并清理 TX 零帧，避免停止输入。修改后观察到非零采样峰值，但尚未据此声称完成语音准确率或声学标定。
- ES8389 按 16-bit 双槽的实际 32-BCLK 配置关闭未验证的 DAC 参考槽；只使用主输入槽，不声明同步双麦或 AEC。
- 用户轻点屏幕后确实触发人脸模型初始化崩溃。根因是 ESP-SR 2.6.1 全局注册的算子裁剪需求移除了旧版 human_face_detect 未申报的 `Concat` / int8 核。组合应用暂时保留完整官方算子与内核，生成文件已确认 `DL_COMPILE_ALL=1`。不修改下载的依赖源码。
- 开始验收时 Mac 构建关闭了旧 LAN 入口，新 WSS 网关也未配置。本轮先在临时目录编译直接引用现有 `lan` / `pairing` / `identity` 源码的诊断进程，使用独立状态目录，不更改正式应用、密钥或配置，不调用模型。此后 Mac 应用的另一次独立更新恢复了默认 `lan-diagnostics`；停止临时进程后，开发板自动发现并连上正式应用的诊断端口。该变化未由本轮固件工作修改。

## 当前边界

- 这里的“尽量耐受断电”指日常运行和重新上电恢复，不能保证任意电气故障或写 Flash 时断电都无损。
- 分区仍是单应用开发布局，没有 OTA 双槽或升级回滚；本轮没有扩大为 OTA 更新系统。
- 完整“小呆小呆”专用声学模型仍缺失。只能使用明确触摸进入会话，不能用其他唤醒词或 VAD 冒充。
- 自动连接的是现有 **LAN v1 诊断服务**，并非已完成 WSS v3 私密语音。固件 WSS 客户端、BLE 配网和 Mac 对话媒体仍待接入。
- 摄像头方向、屏幕映射、声学效果、实际黑屏效果及真实拔电恢复，必须按实测记录判断，不能从源码或构建成功推导。
