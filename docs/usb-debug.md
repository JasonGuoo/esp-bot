# USB 开发预览：屏幕、相机和 Events

用户于 2026-11-07 明确要求将 Bot 屏幕、摄像头画面和事件回传到 bot-server，
用于排查实际无跟随故障。此开发通道复用已连接的物理 USB，不使用未认证 LAN v1
承载媒体，也不声明 WSS v3 语音或 BLE 配网已经完成。

## 入口与数据

`usb-debug.html` 是同一实现的独立开发窗口，不调用对话服务、Keychain 或模型。

当时原主程序的对话服务正在运行，因此没有为替换应用而中断它；新版主程序尚未启动
验收。需要时先正常退出旧主程序，再启动新的应用包；两个窗口不要同时占用同一串口。

- **Bot 屏幕**：使用 LVGL 的最后一次完整刷新对应的全屏缓冲区，在显示锁下复制并
  缩为 400×240 RGB565，再使用官方 JPEG 编码，不为了预览重新渲染界面。它反映
  渲染缓冲内容，不是外部拍摄的 LCD 光学效果，不能用它证明背光熄灭或没有实体
  LCD 的错位和撕裂。要求 RGB565 全屏 direct/full 刷新模式，其他模式报不可用。
- **摄像头**：视觉所有者当前独占的、已处理安装方向的模型输入；新版固件在白天空闲时
  会为近距离表情做本地采集，会话和明确的 USB 调试请求也可请求采集。回调在返回前
  等比缩入 400×240，绝不把 DMA/视觉缓冲指针入队。
  绿框仅绘制在预览副本上，表示该帧模型输出通过了几何检查；它不保证该人脸已被
  注意力模块选为跟随目标，无框也不代表画面里没有人。
  普通预览不会自行请求相机；相机由正常运行时开启后，预览会显示其画面。调试保活
  是另一个明确的本地请求，不创建对话，也不是白天本地人脸检测的关闭开关。

默认只保留内存中的最新帧。仅点击 **导出当前帧** 时，Mac 才把那一帧写到新建的
私有临时目录（0700 / 0600）。事件为有界内存记录，过滤 Wi-Fi 驱动日志及可能含
password/Authorization/token 的行；不包含麦克风 PCM、转写或身份模板。

## 开启与退出

固件功能默认关闭。本次开发烧录显式开启：

```ini
CONFIG_ESPBOT_USB_MANUAL_CONTROL=y
CONFIG_ESPBOT_USB_DEBUG_PREVIEW=y
```

上电后预览仍关闭：

| USB 命令 | 效果 |
| --- | --- |
| `preview on` | 开始有期限的开发预览；不会唤醒设备或启动相机 |
| `preview ping` | 续期已开启的预览，不开启关闭中的预览 |
| `preview off` | 停止预览并清除待发的相机副本 |
| `wake` | 明确的物理 USB 手动动作，向唯一 runtime 发送与触摸相同的有意唤醒事件 |
| `stop` | 通过既有停止锁存结束互动 |
| `camera on` | 显式开启持续 USB 相机调试，即使互动结束后仍可继续本机预览；不发起对话或上传媒体 |
| `camera off` | 关闭额外调试保活请求；白天本地检测或正在进行的正常互动仍由 runtime 控制相机 |
| `eye left` / `eye center` / `eye right` | USB 预览开启且屏幕可用时，手动测试渲染眼睛 10 秒；暂时覆盖自动注视，包括近脸居中，不唤醒对话或控制电机 |
| `face <表情 ID>` | 仅在 USB 预览开启且显示可用时，居中预览指定表情 8 秒，随后恢复自动行为；不启动对话 |
| `camera orient?` | 查询当前期望的相机安装方向 |
| `camera orient 0` / `1` / `2` / `3` | 保存并应用原方向 / 左右镜像 / 上下翻转 / 两轴翻转；视觉流和人脸轨迹重启 |
| `screen frame` | 使用已经刷新的完整帧缓冲，避免为预览重新绘制界面 |
| `screen snap` | 对照实验：对当前活动屏幕重新渲染一次快照；不包含顶层遮罩 |

Mac 每 5 秒重新确认预览开启；15 秒没有续期，板上预览自动关闭。用户本次明确
开启持续相机调试后，同一调试会话中的原 USB 串口恢复时会重新发出该请求；退出或暂停
预览会清除它；这不会关闭由日间近脸反应所需的本地采集。夜间模式、设置页和严重故障期间不执行该调试采集。设备软件重启后
即便串口没有断开，Mac 也会重新请求预览。切换桌面窗口不再暂停，离开设备调试页
则暂停画面，断开时发 `preview off` 并清除 Mac 图像缓存。旧连接的 wake/stop
队列不会自动唤醒重新上电的 Bot。串口打开本身可能使这块 USB-UART 板复位。

串口由一个连接独占。烧录前必须断开调试页的 USB；不要同时运行其他串口监视器。
当前为 115200 baud、低帧率开发预览；真实吞吐和控制延迟以实测为准。
两路画面各自采集、编码和发送，并非同步视频；窗口显示设备端采集时间的差值。
屏幕取帧遇到显示锁忙会在 200ms 后重试，其他取帧失败在 1 秒后重试；成功后仍按
原来的 2 秒间隔采集，以免增加正常情况下的显示带宽压力。

事件中的 `gaze_trace` 区分最终眼位来源：`face` 为有效跟随，`idle` 为自主张望，
`near_face` 为近脸微笑的居中，`manual_eye` / `manual_expression` 为 USB 调试覆盖，
`center` 为其余情况。`focus_milli` 是选中人脸眼部中点的归一化坐标乘以 1000，
无法定位时为 `(-1,-1)`；`target` 是本次请求眼位，`rendered` 是缓动后的眼位，
只有 `rendered_valid=1` 时可用。绿框、目标眼位和渲染帧还需结合各自的时间戳解读。

新版窗口的“表情预览”使用与固件同源的表情目录；手动预览是明确的诊断覆盖，8 秒后
退出。`overjoyed` 才有眼睛反光，不加入日常表情列表或近脸微笑。现阶段正常对话还未
实现能产生“特别开心”语义事件的设备端链路，因此只能手动预览，不声称已经自动识别
特别开心。传统线条主题退回普通开心眼形。

“摄像头方向”通过乐鑫 esp_video 的 `V4L2_CID_HFLIP` / `V4L2_CID_VFLIP` 在传感器
端矫正，预览与检测共用已矫正图像。保存前不更改设备方向；保存成功后记录单字节
NVS，NVS 不可用时不覆盖已有方向，也不自动擦除。切换时会停止并重新开启取流、丢弃
旧人脸轨迹；夜间休息时只保存配置，待相机下次启动后生效。当前板的默认值按用户反馈
设为左右镜像；是否符合实际安装方向仍以现场画面确认。传感器不支持相应控制时会报告错误，
不会把失败当成已实际应用。

## 有界二进制格式 v1

普通设备日志与预览复用串口。一个低优先级写入者发送帧，并异步排队 ESP 日志，
避免行为/采集线程等待整张 JPEG。普通启动信息或异常输出破坏帧时，接收端通过
CRC 和 magic 重新同步。

32 字节小端头：

| 偏移 | 内容 |
| --- | --- |
| 0..7 | `D7 39 58 44 42 47 01 A5` |
| 8 | source：1 屏幕、2 摄像头、3 事件 |
| 9 | encoding：1 JPEG、2 JSON |
| 10 / 12 | u16 width / height |
| 14 | u16 保留，0 |
| 16 / 20 | u32 sequence / device monotonic ms |
| 24 / 28 | u32 payload length / 标准 CRC32 |

负载上限 96 KiB；接收端校验尺寸、长度、CRC 与 JPEG 首尾标记。相机与屏幕是最新
帧槽位，忙时丢弃预览，不回压 runtime；Events 上限 300 条。两路时间戳和事件均使用
同一设备单调毫秒，Mac 另记接收时间。界面明确显示最后一帧的时间和过期状态。

## 显示诊断

USB 预览启用期间每约 15 秒输出 `display_trace`、`preview_trace`：活动屏幕坐标、
滚动位置和分辨率、LVGL 刷新次数与耗时、屏幕复制、相机预览转换、JPEG 和串口发送
耗时以及丢弃日志数。耗时是包含调度等待的墙钟时间，不是 CPU 占用率。截图模式切换
供复现实验；停止预览后回到帧缓冲模式。截图、坐标和滚动值都不能直接观察实体 LCD
的电信号或光学错位。

ESP-IDF 6.1 的 S31 RGB LCD 驱动检测到 underrun 时通过早期串口日志输出
`lcd.rgb: LCD underrun`，它可能插入 JPEG 数据中。Mac 接收端在原始字节流上计数，
同时原有 CRC 校验仍会拒绝受干扰帧；没有此日志不等于证明 LCD 从未欠载，因为串口
或日志可能丢失。

### 与上游示例的区别

- [乐鑫 S31 原厂示例](https://github.com/espressif/esp-dev-kits/blob/master/examples/esp32-s31-korvo/examples/factory_demo/main/main.c)
  是板载外设面板，创建不可滚动的 240×240 相机区域；其
  [相机代码](https://github.com/espressif/esp-dev-kits/blob/master/examples/esp32-s31-korvo/examples/factory_demo/main/factory_demo_camera.c)
  使用 PPA 对相机画面缩放/转换。此处 USB 双画面只是 Mac 端的调试视图，不在实体屏幕
  上创建画中画，也不改变 800×480 的显示尺寸。
- [乐鑫 Emote 服务](https://docs.espressif.com/projects/esp-brookesia/en/latest/service/expression/emote.html)
  加载表情资源并按名称切换表情、动画和消息；
  [底层组件](https://github.com/espressif2022/esp_emote_expression)提供眼睛动画播放。
  目前没有证据表明其命名动画 API 已提供连续人脸位置驱动的瞳孔坐标接口。
- [社区小智 S31 板级代码](https://github.com/78/xiaozhi-esp32/blob/main/main/boards/espressif/esp32-s31-korvo-1/esp32_s31_korvo_1.cc)
  使用 `RgbLcdDisplay`、16 MHz 像素时钟和 8 行 bounce buffer；源码注释称过大缓冲会
  挤占内部 SRAM。它是社区实现，不是原厂示例；上述参数不是本项目经过验证的修复。

## 验证状态

镜头转正后，前一版设备曾多次记录 `model_faces=1`、`faces=1`，相机预览同时出现
人脸绿框；这只证明当时现场的人脸检测。2026-11-07 的诊断版已烧录并校验：两路
USB 画面和持续相机采集可用；软件画面左右眼位各移动约 26 个预览像素；开启持续
调试后，在闲置及普通睡眠状态相机均保持采集，Mac 两路画面持续更新。切换桌面窗口后
屏幕预览继续更新已实测。实体 LCD 错位是否消除、真正拔线重连与人脸跟随仍需相应
实测，不能仅根据 UI 帧或日志认定通过。
最新结果同时记录在 [首次实板记录](board-bringup-2026-11-06.md)。无 CI。
