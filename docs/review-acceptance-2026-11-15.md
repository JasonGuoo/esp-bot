## 验证中修正的问题

1. **真实 IDF 编译发现遗漏的事件名称**：USB 事件名称表补齐 `turn.submitted`。
2. **应用超过 8 MiB 分区**：复用官方 ESP-DL `compile_register` / `compile_finalize`，为固定的 MSR/MNP S8 模型登记 Conv/Concat/PRelu 和每张量 int8 内核，保留 ESP-SR 自己的音频依赖。模型 SHA-256 改变即停止配置，不能静默裁掉新模型依赖。不修改 managed components，不删字体或 104 条离线音频，不改分区表。
3. **MultiNet 与相机并行时无法分配 DVP 备用帧**：V4L2 从三帧改为官方支持的双帧队列，推理仍使用自己持有的 packed 副本，并在推理前归还 DMA 帧。之后实板恢复连续采集/推理。增加 PSRAM 总空闲/最大连续块诊断。
4. **正确唤醒结果被误拒绝**：实板出现 `command_id=1`、原始模型分数 0.996，但旧代码把 `phrase_id` 当成零起始的命令数组索引。改用已安装并逐项核对的稳定 `command_id`，仅接受最高候选、当前图中的完整唤醒词或授权固定命令。内部 phrase ID 不再承担授权。
5. **低音量语音被额外静音门限截断**：删除第二个固定 −48 dBFS / 600 ms 清理逻辑，使用官方 AFE 的语音→静音边界清理部分命令；全部帧仍进入识别器，以保留 VAD 确认前的起音。权限关闭立即清理。没有增加识别器、预唤醒录音或上传缓存。
6. **Mac 正常退出后设备仍保留认证状态**：把官方 `WEBSOCKET_EVENT_CLOSED` 纳入与错误/断线相同的权限撤回路径，沿用官方 `enable_close_reconnect`，避免下一次本地唤醒使用已关闭的 Mac 会话。
7. **macOS 婷婷名称变化使 TTS 被误判为未安装**：安装列表去重；短名称仅在唯一匹配已安装的带语言后缀名称时解析，模糊或缺失名称仍拒绝。真实合成得到有效的 16 kHz 单声道 PCM16 WAV，没有下载声音或切换语言。
8. **Mac 录音无限等待**：显式调用官方 AVCaptureDevice TCC 授权，再打开 WebKit 媒体流；等待有界、重复待定请求合并、迟到流按采集代数立即关闭。主窗口本地来源才允许 WebView 采集，Permissions-Policy 限制远程卡片的麦克风/相机访问。控制台单段录音在停止播放后使用普通输入，不开启双工 VoiceProcessingIO。系统授权的实测限制见下文。
9. **官方 AGC 的输入/输出帧长不同**：实板 WebRTC AGC 为 feed=160、fetch=512。移除错误的等长约束，仍由唯一采集 worker 按成功 feed 的采样量累积、非阻塞获取完整输出；清理 native ring 时同步清理累计值，连续 4 秒无输出才判故障，避免等待下一次尚未 feed 的输入而堵住采集。沿用官方 AGC compression 12 dB / target −9 dBFS，仅识别分支处理，上行继续使用原始 ADC 通道。
10. **启动主任务栈溢出**：AGC 对照版本实板捕获到 `main` 栈溢出及随后一次字体路径的访问异常。启动栈由默认 3,584 提升到 8,192 字节，返回前报告实际最小空闲水位；`app_main` 返回后释放这块栈。最终版本的重启结果在下表单列，不把配置增大本身当作通过。
11. **AGC 后的空追问**：一次回复完成后出现没有合成输入的 VAD 起音，Mac 拒绝为 `audio_too_quiet`。追问增加独立的原始 ADC RMS −42 dBFS 判断，仅使用授权且 RX fence 后的输入，保留 320 ms 能量证据时间戳对齐官方 AFE 延迟；所有权限/播放/恢复清理一并撤回。已经起音后的轻音节仍跟随正常 VAD 结束。新增整型 RMS 边界、满幅/空输入和“VAD 有语音但原始底噪不足”回归，ASan/UBSan 通过。

固定命令的较长合成语音存在漏识别，新增“大声一点/调大音量、小声一点/调小音量、静音、取消静音、换蓝色、重播”等同意图别名；原命令仍保留，固定命令分数门限仍为 0.85，别名仅进入已授权会话词表。声学结果必须按下文实测逐项认定。

## 最终镜像与收尾复测

最终 factory 镜像为 **8,326,912 字节**，SHA-256 `7d1f676fc893a6ccf287cda521aad1104c3b5af3dad0e9473e113d5b9d0f2347`；仅写入 `0x10000`，esptool 写后哈希校验通过。以下语音复测使用包含原始 ADC 追问起音修复的最终镜像：

1. 通过 Bonjour 和已配对凭据重新认证，完整唤醒分数 0.995；实际 `mic:1 link:1` 后播放问题，提交 543 帧。
2. 本地 RMA Qwen ASR → GLM Coding Plan → Mac TTS → 设备文本绘制与硬件播放，首轮 `finished` 为 381 帧 / **243,384 字节**。
3. 实际硬件完成后进入 WAITING，预备同一下一轮 token 并重新就绪；**安静等待 5 秒，没有自行起音、提交或进入思考**。
4. 播放“刚才测试的是什么？用一句话回答。”，实际转写与该句一致，提交 631 帧；回复保留上一轮设备对话上下文，并完成 444 帧 / **283,800 字节**的第二次硬件播放。Mac 页面显示处理约 7.0 秒，其中 ASR 125 ms、OpenCode 5,985 ms、TTS 930 ms；USB 渲染帧中文字可读。
5. 在前一轮实板 THINKING 时点击控制台“新对话”，设备继续完成其回复和播放，没有被控制台空 turn 取消；后续空追问另由 `audio_too_quiet` 终止，二者没有混为同一失败原因。脚本最初等待 USB 未出现的提交事件而误超时，改用实际 `Plain LAN audio submitted` 日志后，最终受控链路 9 个检查全部通过。保留原始失败记录，不将脚本修正冒充固件修正。

## 已确认的验收边界

- Mac 原生录音推进到系统 TCC 授权后，自动化工具明确拒绝操作 `com.apple.UserNotificationCenter`，理由为安全限制。没有修改 TCC 数据库或绕过系统授权；因此 **Mac App 直接录音尚未完成验收**。取消/超时能回到可操作状态；设备麦克风与 WAV 输入链路可独立验证。
- 摄像头本次朝向桌面与线缆。有效采集/推理不能证明人物定位、真实人脸跟随或眼神互视。本次不以无人的画面声称这些效果通过。
- `playback.started/progress/done` 及硬件写入计数证明 codec 播放链路推进，不能单独证明扬声器实际接线、声压、失真或实体 LCD 的光学效果。没有远程假装移动摄像头、插接扬声器或安装电机。
- Mac 人脸/声纹环境检查仍显示缺少 cv2、speechbrain/torchaudio 等资源，BLE、OTA/rollback、AEAD 媒体和数据分区资产迁移不在这次已实现验收范围内。

复用依据：[官方 S31 MultiNet/AFE 接口](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s31/speech_command_recognition/README.html)、项目固定版本的 ESP-DL 编译登记、esp_video/V4L2 与 LVGL pointer 示例、[Apple 媒体授权 API](https://developer.apple.com/documentation/bundleresources/requesting-authorization-for-media-capture-on-macos)，以及本机 Tauri 2.12.5 / Wry 0.57.1 实现。没有新建声学识别框架或媒体传输替代品。
