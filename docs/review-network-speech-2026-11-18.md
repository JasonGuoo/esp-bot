保留 VPN 开启，通过当前 Wi-Fi `en0` 分别运行不带密钥的端点检查和官方 OpenCode 2.2.5 的合成聊天请求。记录连接绑定的网卡、HTTPS 连接的实际对端 IP 和服务商返回的 HTTP 状态。

| 服务商 | OpenCode 实际出口 | 聊天接口使用无效测试密钥 | 不带密钥的端点检查 |
| --- | --- | --- | --- |
| 智谱国内 GLM | `en0` · IPv6 | 401 | 401 |
| DeepSeek | `en0` · IPv4 | 401 | 401 |
| 千问（仅在隔离测试中启用） | `en0` · IPv4 | 401 | 200 |

不同轮次的 GLM 请求连接了两个不同的 IPv6 对端。系统默认 DNS 当时未返回智谱的 AAAA，Wi-Fi 配置的 DNS 返回了可用的 IPv6 地址。IPv4 网关当时未响应 DNS 查询。HTTPS socket 始终绑定物理网卡，DNS 查询采用系统路由。三家返回的鉴权拒绝证明请求到达服务商，本轮的测试密钥无法生成模型回答。

本机已安装的控制台在 **模型与密钥 → GLM → 测试网卡直连** 显示「直连成功 · en0 · IPv6 · HTTP 401」。正式配置以 GLM 为首选、DeepSeek 为备用，千问停用。

## 较早的网络测试（GLM 国际站）

当时普通外网路由经 `utun6`，活动 Wi-Fi 为 `en0`。分别检查不带密钥的 `/models`、带故意无效凭据的聊天请求，以及官方 OpenCode 经本机转发发出的独立合成回合。表中状态来自实际供应商 HTTPS 连接；本地返回的 502 不算供应商响应。

| 服务商 | 在本机看到的结果 |
| --- | --- |
| DeepSeek | `/models` 返回 401；聊天接口和官方 OpenCode 回合在 `en0` 收到 401。 |
| Qwen | 修复转发时丢失客户端标识的问题后，`/models` 返回 200；聊天接口和官方 OpenCode 回合在 `en0` 收到 401。未验证套餐是否允许正式使用。 |
| GLM 国际站 `api.z.ai` | 曾通过 `en0` 在 `/models` 和聊天接口收到 401。随后 CDN 解析到另一组地址，系统没有通往这些地址的 `en0` 路由；用同时期解析结果和独立 TLS 客户端复现。最后一次正式 OpenCode 回合未取得上游 HTTP 响应，转发报错且没有切回 VPN。 |

该轮测试选择活动物理接口，重用连接前也检查活动网卡，并校验服务商域名的 TLS 证书。测试期间保留系统路由与 VPN 设置，按当时 DNS 查询所得地址连接。国内端点的后续复测见本页首节。

本机 75 项常规 Rust 测试全部通过。两项可选真实网络测试分别检查三家端点和三条正式 OpenCode 请求，最后一次两项都因 GLM 直连失败未通过；DeepSeek 和 Qwen 均得到预期的鉴权拒绝。本次运行没有有效模型凭据，没有成功生成云端回答，也没有验证账户余额、生成内容或首字延迟。
