# 身份连续性：先有相处，后来才知道名字

日期：2026-11-25。源码基线：`46ecdfbd99eba8e9158f8953b9ca251a45bc1d92`。总跟踪：[issue #36](https://github.com/JasonGuoo/esp-bot/issues/36)。关联：[能力契约](capabilities.md) · [RA-07](steps/ra-07-identity-continuity.md)。

**状态：拟议用户能力，尚未实现。** 现有声音相册、控制台命名、模板识别与人工纠正作为复用基础保留；本页要求新增的是对话中的身份理解、可信绑定、持续工作流和可解释回执。本次不修改运行代码、数据库或留存设置。

## 1. 用户场景与成功定义

用户可能已经与小呆聊过多次，才说“记住，我是 Jason”。小呆应立即承接这句话，先可靠保存可确定的称呼，再根据已存在的声音证据建立识别关系，并仅在证据足够时关联旧对话。知道名字不应要求重新开始所有关系；知道一个名字也不能证明设备全部历史都由此人产生。

完整能力包括：开始、查询进度、补充样本、处理冲突、跨回合恢复、解释可关联的历史范围、更正误认、删除声音，以及传播到相关记忆。它不要求每次从用户口中收集完整姓名，不把匿名访客强行登记成家庭成员。

成功的自然语言反馈必须对应实际状态：

| 已发生的事实 | 可用回应 | 不可声称 |
| --- | --- | --- |
| 当前自我介绍的称呼已保存，声音未绑定 | “Jason，称呼记住了。声音还没绑定。” | “以后我一定听声音就认得你。” |
| 当前合格声音已与人物记录绑定 | “记住了，Jason。”；需要解释时说明声音也已关联 | 百分之百识别、无需任何后续核对 |
| 有一部分旧片段可靠关联 | “我把能确定是你说的那些记录关联好了。” | 所有以前对话都是 Jason |
| 只有文本，没有可匹配的声音证据 | “称呼记住了；以前没留下可匹配的声音，不能靠声音补认。” | 根据文风、同一设备或相同话题追认声纹 |
| 持久化失败 | “刚才没保存成功，我可以再试一次。” | 因为已说出口就报告记住 |

句子只是产品示例；不可将未确认阶段的承诺提前冻结到已播放语音。普通回答不等待声纹，身份工作流也不阻塞继续聊天。

## 2. 当前源码已有的基础与真实缺口

[`memory/voice_album.rs`](../../../server/bot-server/src-tauri/src/memory/voice_album.rs) 已有匿名声音发现。每段录音的 diarization label 不跨录音直接比较；用保留的合格样本、精确 `model_id`、相似度 floor 和领先第二名的 margin 选择组。组可以暂无 `person_id`，控制台可以后来命名，并将未来匹配作为 `automatic_person_id` 候选。

现有命名与拆分考虑组 revision 和单条人工标注：独立人工决策优先于组级命名。已有回归源码包含 `discovers_without_enrollment_and_names_past_and_future_turns`，因此不能把本系列描述为从零增加匿名聚类。这条测试的存在也不等于本次运行通过或真实家庭声学准确率已验证。

现有收集边界必须保留：

- `voice_review_enabled` 默认关闭，`voice_review_generation` 防止关闭后迟到推理重新写回；开关变化推进 generation，关闭时清除声音组/片段。
- 只收集显式激活后的共享音频；私密来源、已遗忘/过期来源、旧 generation 不进入声音相册。
- `single_speaker_verified=true`、`overlap=false`、`quality_ok=true`；基线片段窗口为 3–6 秒且有字节上限。
- 基线相册最多 256 个片段，另有 30 天最大年龄；家庭留存/删除可能更早使来源失效。这些是当前实现限制，不是识别性能保证或本系列新的推荐阈值。

[`memory/identity.rs`](../../../server/bot-server/src-tauri/src/memory/identity.rs) 是另一条显式模板登记路径：既有 `guardian_confirmed`、样本数、一致性、精确模型版本和显式替换等要求不能被模型伪造参数绕过。声音相册组关联和模板 enrollment 是不同机制，结果应记录采用哪一种依据。

缺口在于：现有 `household.voice.name` 等是控制台操作；`rpc.rs` 的相关 mutation 会全局取消并持有 turn gate；fast core 禁用工具，没有高层对话身份工作流、三种结果状态和非阻塞回执。因此不能直接把管理 RPC 暴露给 Luna/OpenCode。

## 3. 人、声音、姓名和来源分开建模

| 概念 | 权威来源 | 规则 |
| --- | --- | --- |
| 原始话语/说话段 | household turn/segment、样本范围、来源 revision | 原始记录保留来源；可追加修订，不能将新说话者的音频挂到旧轮次 |
| 匿名声音组 | `voice_groups` 与有效 `voice_clips` | 可合并/拆分，成员和 revision 可变；组 ID 不是身份认证 |
| 人物实体 | `profiles.id` / 领域 `person_id` | 稳定 ID，可以暂时只有自报称呼；显示名字不充当主键 |
| 姓名与别名断言 | 明确自我介绍或可信人工更正及其来源 | Jason/杰森可以是别名；同名不自动合并，改名不覆盖另一人的模板 |
| 当前声音匹配 | 当前来源的有效自动证据、人工标注 | 模型/前处理一致，质量和冲突可查；不确定保留 unknown |
| 历史归属 | 来源级匹配或明确人工指认 | 用户确认和声学匹配是两种证据，不互相冒充 |
| 权限主体 | 已有可信宿主授权/控制台身份 | 不能因名字、声音或人脸候选被提升 |

拟议新增持久记录保存名字断言和绑定结果的来源、revision、policy generation、操作 ID，以及所依赖的声音组/样本版本。不要复制一套 profiles 或另建人员数据库。

说话者与事实主体不同。Jason 说“妈妈喜欢紫色”，source speaker 是 Jason，事实主语是妈妈；任务的提出者、执行者、受益人也要分开。身份晚到只修正对应来源的 speaker 关系，不能把该轮出现的一切人物和偏好移给 Jason。

## 4. 三组独立状态与回执

不能只存一个 `identity_registered=true`。拟议操作快照至少包含：

| 轴 | 状态示例 | 成功依据 |
| --- | --- | --- |
| `name_state` | `unknown / claimed / saved / conflict / revoked` | `saved` 要有称呼/人物关系的数据库提交回执；只听见一句话仍为 claimed |
| `voice_state` | `unavailable / insufficient / candidate / bound / conflict / revoked` | `bound` 要有有效声音依据与绑定事务；记录 `basis=album_group/enrollment`，不能把模型文件存在当 bound |
| `history_state` | `no_evidence / candidates / linking / partial / linked / revoked` | 对已核验来源集合及版本的关联完成；`linked` 的范围必须有限且可枚举 |

同时带工作流状态、尚缺信息、可选下一步和有限的 `linked_count/rejected_count/pending_count`。这是对已有 task/operation 状态的领域投影，不是新的调度器。长工作流的权威状态在 TaskService，使用 `task_id`、`task_revision`、任务 `input_revision`、attempt 和 checkpoint revision；memory 只持有身份断言/绑定的领域事实与短动作账本，不再保存一份竞争的 workflow 状态。`name_state=saved` 不推出 `voice_state=bound`；声音 bound 不推出全部历史 linked。

名字可先保存，身份推理稍后补充。异步结果必须指向原 self-introduction 操作的可信来源和 revision；不能用“现在最新的一段音频”补到之前名字上。若原输入已经被纠错、删除、切换留存 generation 或撤权，结果失效并返回明确状态。

## 5. “记住，我是 Jason”的宿主流程

1. 授权输入进入既有 household journal；ASR 与身份分支独立。宿主给本次 self-introduction 保留精确 SourceRef/utterance/segment 范围和适用政策版本，原始声音不会发送给前台 LLM。
2. Luna 根据语义提出 `identity.remember_self`，仅包含称呼和 `target_handle=current_speaker`。引述“他说我是 Jason”、故事角色、演练台词和否定句不等于当前用户自报身份；提案还需结合本轮实际用户意图。
3. RA-05 dispatch 用可信当前输入绑定“我”。多说话者、ASR 与分段不能可靠对齐、文本输入没有当前音频时，不猜一个声音组。可以保存本次自报称呼及来源，但报告声音未绑定。
4. 依据已有人员/别名关系解析目标。无冲突时创建/更新称呼断言；同名、显式改名或已有相反标注时进入短消歧。默认不重复询问用户已明确授权的保存称呼。
5. 短事务提交称呼与幂等记录，产生真实 applied 回执。若声音证据已足够且该行为在当前政策范围内，可同轮绑定；否则只报告 name_saved，工作流进入候选/补样或依赖不可用。
6. 复用当前有效相册片段或已确认模板，校验 model_id、single-speaker、overlap、质量、组 revision、来源与 generation。既有相册关闭时不能自动打开；相册启用之前的迟到任务不能趁本次命名写入历史。
7. 如需补样，持续任务记录 `needs_input` 和目标身份；下一次有效授权输入经宿主确认是该补样后继续。不能打开无期限收音，不能因工作流仍在而绕过下一次唤醒/触摸。
8. 历史回查在后台执行，前台可聊天、查询、取消；关联结果经统一收件箱/快照回流，不直接播音。不支持或无证据时明确结束为 partial/no_evidence。

名字保存/补样操作使用已有授权政策。模型不得填 `guardian_confirmed=true`。若某条 enrollment/替换路径按当前政策仍需要可信控制台授权，返回 `needs_authorization` 并保留已保存的称呼；无需把“保存名字”连带阻塞。未来修改授权方式必须单独评审，不由此规格暗中放开。

自动 history 留存与显式“记住这个称呼/事实”分开。history 关闭时，如当前政策仍允许用户明确保存信息，可只保存称呼及必要的最小来源证明；不自动保留整段对话、原音频，也不开启 voice review。没有相关持久化权限时明确说明本次临时使用的范围，不能虚报跨会话记住。

## 6. 晚命名与历史关联

| 历史留存条件 | 允许的操作 | 不能做的事 |
| --- | --- | --- |
| 有当前有效匿名组和合格片段 | 在既有组证据基础上绑定人物，逐个保护人工标注并登记关联范围 | 不经检查给所有同设备/同日内容改名 |
| 只有有效原音频及来源 | 经授权在后台重新分段/提特征，形成可修订候选 | 不能把一份多人音频整体登记成 Jason |
| 只有逐段特征、精确模型/前处理版本 | 在兼容模型空间比对；保留来源和质量边界 | 相同维度不表示不同模型向量可比较 |
| 只有平均组向量，没有片段证据 | 只能在其可靠边界内提示候选；无法支持的拆分保持未知 | 不能承诺可恢复被混合的每个人 |
| 只有纯文本 | 可让用户明确指认具体旧对话，记录“用户确认”的归属 | 文风、话题、时间、设备相同不能变成声学验证 |
| history/voice review 以前关闭，或来源已过期/删除 | 从当前允许的来源建立关系；继续现有文字任务的合法状态查询 | 不能重新生成被删除声音或扩大留存范围 |

自报“我是 Jason”允许绑定当前可靠声音实体，不默认确认整个聚类中所有成员。现有控制台 `edit_voice_group` 的组级人工命名是较宽的操作；自然语言适配器需新增明确的候选集/期望 revision 参数与来源级验证，不能假装同一个 UI 操作已具有上述限制。已有单条人工标注优先规则必须复用。

需要回问时，选代表性、有合法来源的候选，如“昨天让小呆找动画的那次也是你吗？”；不朗读其他私密主体的内容。用户回答只关联其明确指认的范围，不无限扩展到相似声音。

## 7. 纠错、别名、删除与派生传播

### 7.1 更正的优先级

单条明确人工更正 > 该片段已有组级确认 > 当前自动候选。新组命名不能覆盖不一致的单条人工标注。实现使用当前 annotation/group/source revision 作 compare-and-set；冲突后重读候选，不能静默最后写入者获胜。`reset`、显式 unknown 和“这个不是我”有不同语义，保留现有标注体系。

“Jason 是我常用名”可以添加名字断言；“不要叫我 Jason，叫我杰森”通常修改称呼偏好，不重做声音；“刚才不是我说的”修正指定话语，不删除整个人。重名不合并；正式 profile 合并/模板替换沿用可信管理授权。昵称合并不授予私密资料访问权。

### 7.2 撤销传播

人工撤权、遗忘及会使现有内容不再合法的更正，先由控制域发布有范围的 policy/source fence 阻止旧读取与输出，再由后台提交权威关系修订和清理 outbox；数据库尚未提交时不能说已删除。提交失败则该范围保持暂不可用，不能为让聊天继续而重新放出已要求撤销的内容。提交后再清理受影响上下文、摘要、Graphiti 派生关系、检索缓存和作品来源，失败保留可重试记录。RA-06 的快照在后续请求使用新版本，旧 Luna 线程按来源范围失效，不能让旧 prompt 中的名字永久有效。

自动晚到候选与人工纠错的影响不同：自动候选更新不应全局取消正在进行的普通回答；人工撤权/遗忘要及时阻止相关旧内容和副作用。影响范围按来源依赖计算，不能用所有任务全局取消代替精确失效。跨存储不假装有原子事务；复用既有 source cleanup/outbox 和幂等恢复。

已执行过的工具和物理效果不重放，也不因为改标而抹掉发生事实。`task requester` 的来源解析可以更新；任务授权主体仍保持当时可信授权记录，不能因为声音新名字成为管理员。已交付音频保持不可变的交付事实，若内容错了可以新增纠正说明。

### 7.3 删除范围

| 请求 | 默认解释与需处理范围 |
| --- | --- |
| “别叫我这个名字” | 修改当前称呼断言，不自动删除声音或任务 |
| “忘记我的声音” | 撤销目标 person 的声音关联/模板及可再识别特征、相册声音映射和缓存；保留姓名/别名、未要求删除的文字记忆及合法任务，更新 voice_state |
| “那次不是我说的” | 撤销指定来源归属并重算派生主体关系；禁止后到自动候选覆盖 |
| “忘记这次对话” | 按原有来源删除政策处理音频、特征、摘要/索引/作品依赖；保留必要且不含被删内容的效果结算事实 |
| “删除我的资料” | 必须解析为明确 person 和范围；复用现有 profile 删除政策，不能误删其他家庭成员的共享来源 |

声音相册与显式 enrollment 是两类存储；实现“忘记声音”必须覆盖实际存在的两类及 profile alias 来源下仍可用于识别的声音模板/映射。这里不要求删除名字别名、profile 合并关系或文字记忆，除非用户明确扩大删除范围。不能声称擦除了不可访问的外部备份或已经播放给人的内容。

“忘记既有声音”与“以后不要识别我的声音”还需区分：前者删除已有证据并阻止其迟到重建，后者另保存持续不识别偏好。两者都不能在后台靠旧结果、再次命中匿名组或自动新样本悄悄重建同一 person 的声音绑定；未来重新登记需新的明确意图及宿主政策，重复说名字不等于撤销这个选择。可以保存不含声纹的撤销记录/人物偏好，用于阻止已知人物的自动绑定；不得保留被要求删除的声纹来暗中识别并执行 opt-out。

若所有声音特征已删除，系统无法可靠判断一个全新匿名声音是否来自该 person。因此持续不识别偏好不能被夸大为“在共享设备任何新声音中都能自动排除你”；实现应说明该边界，并通过当前会话显式身份、受信管理选择或家庭声音收集设置落实可识别的范围，不能以恢复旧声纹弥补这一限制。

## 8. 可回放的验收场景

| ID | 用户与事件顺序 | 应有结果 |
| --- | --- | --- |
| ID-01 | 先聊三次→形成匿名组→“记住，我是 Jason” | 名字保存，可靠当前声音绑定，只关联有效候选；不另起无历史的人格 |
| ID-02 | 同句自报，模型未加载 | name saved；voice unavailable；不能说已经认住声音；聊天继续 |
| ID-03 | 自报后声纹迟到，此时另一人开始说话 | 结果仍绑定原 SourceRef；不挂到最新人/音频 |
| ID-04 | 自报后关闭 voice review，再开启，旧结果抵达 | generation 不符，旧结果不能入库 |
| ID-05 | 同名两人、另一人说“我也叫 Jason” | 不按名字覆盖模板；产生可解释冲突或新人物 |
| ID-06 | 父子先被误聚类，某条已有独立人工标注 | 组命名不能覆盖单条标注；可拆分、更正并传播 |
| ID-07 | 两人同时说“我是…”或快切轮次 | unknown/needs_input；不将混合片段登记到任一人 |
| ID-08 | 旧记录只有文本/声音已删除 | 无声学回认；具体用户确认有独立 provenance |
| ID-09 | 旧特征模型 A，当前模型 B，向量维度相同 | 不直接比较；有合法原音频可重提，否则保持 unknown |
| ID-10 | “妈妈喜欢紫色”后身份补齐 Jason | speaker 更新，事实主语仍是妈妈 |
| ID-11 | “那次不是我”与历史回查并发 | revision/fence 保护人工纠正；旧回查不能覆盖 |
| ID-12 | 声音删除中进程退出，重启后结果/缓存迟到 | 恢复清理，不复活识别，不重放工具，无权限变化 |
