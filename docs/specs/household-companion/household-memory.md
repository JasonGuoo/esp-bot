# 家庭会话与可追溯记忆设计

日期：2026-11-16。状态：**已确定的目标设计，尚未实现**。源码观察基线为
`90972a37530b68b8c8c9729960ac15e901c9d946`；当前接口和迁移规则仍以
[Mac 记忆实现说明](../../mac-memory.md) 为准。本规范与
[总设计](README.md)、[开发步骤](implementation-plan.md) 配套，主要覆盖
HC-02、HC-04、HC-09、HC-10、HC-11。

## 1. 产品模型：一家人的共同经历

家庭是会话与知识的组织空间。父母、孩子和访客是参与者或被谈论的人物，
不会因为声纹候选变化而把同一个话题拆成多个个人聊天窗口。人物页面是家庭记录的
筛选视图，可以看到这个人参与的对话、相关事件和已知信息；它不创建另一份记忆副本。

用户每天看到一个家庭对话记录，内部按连续互动、话题切换或任务边界形成有界片段。
同一天再次唤醒继续追加；第二天可以引用前一天的话题、图片和任务。
“当天一个对话”是产品中的归档方式，不代表麦克风全天开启，也不代表把全天文字
无限塞进一个模型请求。没有显式唤醒或授权互动时，保持现有禁止环境音上传的门控。

家庭共享也不等于把历史个人资料全部公开。旧记录的本地专用、个人可见和云端使用限制
在迁移时保留。知识空间、记录可见性、当前听众以及是否可交给当前模型分别判断。
声纹用于标注来源和改善称呼，不承担家长权限或工具授权。

## 2. 目前代码的边界

| 当前实现 | 新目标及对应步骤 |
| --- | --- |
| `memory/store.rs::register_conversation()` 将 conversation 不可变地绑定一个 profile 或匿名 | HC-02 建立家庭日记录；参与者作为关联表和逐句标注，不改绑旧 conversation |
| `TurnRecord` 没有完整逐段说话者、发生时间、引用跨度和呈现回执 | HC-02 增加原始输入及修订记录，HC-03 提供异步身份结果，HC-07/08 记录真实输出 |
| `history_enabled=false`，启用后的默认 TTL 为 24 小时，最多 24 条 role 记录 | 新家庭模式要有独立、可配置的长周期文字留存；不能沿用 24 条截断作为一整天的档案 |
| `brain/mod.rs` 在模型调用前入队记忆任务，但在图片/TTS 成功后才追加 user/assistant 历史 | HC-02 先持久化用户来源；失败、取消和迟到的身份仍可解释，不能只有提取结果没有原文 |

| 当前来源常为 `auto:<conversation>`，待归属观察分配后的记忆不足以定位完整原文跨度 | HC-02/10 使用稳定 turn/segment/source revision，分配或改名不丢来源 |
| 当前正文摘要抑制仅防止已有任务再次写入同样的正文 | HC-10 按来源版本、删除墓碑和派生依赖阻止改写后的旧事实复活 |

这里列出的是设计迁移原因，不把旧 API 的所有限制都称为 bug。已有的
[#9：动态召回导致 OpenCode 会话被删除](https://github.com/JasonGuoo/esp-bot/issues/9)
仍需单独修复；文档更新不会关闭它。

## 3. 权威数据与标识

**SQLite 保存权威原始记录、身份修订、任务状态、派生物版本与删除意图；Graphiti 是可重建的检索投影。**
OpenCode session 的工作上下文、图数据库和每日摘要都不能替代原始档案。

| 对象 | 必须包含的字段 / 语义 |
| --- | --- |
| Household | `household_id`、显示名、家庭 IANA 时区、可见性与目的地策略版本 |
| DailyConversation | `daily_conversation_id`、`household_id`、本地日期、创建时使用的时区；一个家庭日期对应一份用户记录 |
| Episode | `episode_id`、所属日记录、开始/结束原因、涉及的 `topic_ids`；长度/字节/token 受预算限制 |
| ConversationTurn | `conversation_turn_id`、原始输入类型、`utterance_id`、ASR 文本/版本、发生与接收时间、状态；不是固件 `RuntimeToken.turn_id` |
| SpeakerSegment | `speaker_segment_id`、`utterance_id`、音频样本区间、说话者候选/已标注人物、判定来源、模型版本和修订号 |
| Person / relation | 稳定 `person_id`、显示名/别名、显式家庭关系；与已有 `person_...` profile ID 可映射 |
| Topic / event | 跨天稳定 topic ID、事件起止/时间不确定性、参与者、状态、全部来源引用 |
| MemoryClaim | 内容、主语实体、断言类型、有效时间、来源集合、确认状态、可见性、目的地策略、修订号 |
| DerivedDocument | 日记、话题摘要、学习观察等；输入截止序号/来源修订、提取器与 schema 版本、产物状态 |
| Artifact / receipt link | `task_id`、`presentation_id`、不可变资产版本、实际呈现或执行回执引用 |

`activation_id`、固件原有 runtime token、`output_lease_id`、OpenCode session ID
分别控制收音、设备新鲜度、输出资格和推理上下文。它们均不能复用为
`daily_conversation_id`。任务可跨越唤醒、断线或午夜，结束后仍挂回发起它的记录，
但不会自动获得新一轮设备播放权限。

### 时间与午夜

记录 `occurred_at`（发生时间）、`recorded_at`（服务端接收时间）和音频相对样本区间。
设备单调时钟只能在对应捕获会话内比较，不能直接当作 Mac 的 UTC 时钟。
迟到的片段按已知发生时间归档，接收时间保留用于排查；时间不可确定时显式标记。

午夜不切断正在说的一句话、不取消打印或画图。输入以开始时间归属日记录，跨日区间
保留实际结束时间；次日新输入建立新日记录，并通过 episode/topic/task 引用保持关联。
修改家庭时区影响后续分日，不能静默重写历史日期或产生重复日记录。

## 4. 先记来源，再产生记忆

一段已激活输入在可用 ASR 文本产生后先写入 SQLite，随后才提交前台推理和后台整理。
如果 ASR 或存储失败，记录可表达的失败状态并按能力降级；不能向用户声称该段已经记住。
音频本身是否留存由独立设置控制，短期推理缓冲不等于录音档案。

来源引用结构至少包含：

```json
{
  "conversation_turn_id": "ct_...",
  "speaker_segment_id": "seg_...",
  "source_revision": 2,
  "text_span": { "start": 0, "end": 9, "unit": "unicode_scalar" },
  "quote": "妹妹最近喜欢恐龙。",
  "speaker_person_id": "person_father",
  "subject_entity_ids": ["person_daughter"],
  "assertion_kind": "reported_statement"
}
```

示例字段是待实现契约，不是现有 wire API。跨度必须指向同版本原文，引用文字必须匹配；
模型无权编造 source ID 或将摘要本身伪装成一手证据。
父亲说“妹妹最近喜欢恐龙”，说话者是父亲，事实主语是女儿，断言性质是转述。
不能据此生成“父亲喜欢恐龙”，也不能冒充女儿本人已确认。

普通家庭问题无需等待声纹完成。未知、多个候选、重叠说话和样本不足都可保存；迟到身份
结果只追加该来源的身份修订，并触发相关派生物更新，不重放回答、不重开日会话、
不追溯批准打印。原始自动候选与人工标注并存，人工修正有来源和修订记录。

## 5. 后台整理产物

| 产物 | 内容 | 不允许的推断 |
| --- | --- | --- |
| 当日事件 | 发生了什么、谁参与、时间、结果、未完成事项与任务链接 | 把模型建议记为已经发生；把打印提交记为纸张已经输出 |
| 话题线索 | 今日/跨日讨论的主题、共识、疑问、下次可继续的位置 | 每天重新创建同名人物或切断同一跨日计划 |
| 学习观察 | 学习者、知识点、实际互动证据、提示程度、后续练习建议 | 机器人讲过或孩子说“懂了”就标为掌握 |
| 长期事实与关系 | 明确偏好、家庭关系、持续计划、事实变化及有效时间 | 把随口举例、角色扮演、搜索网页中的第三方信息变成家庭事实 |

学习证据至少区分 `introduced`（听过/看过）、`self_reported`（自称理解）、
`correct_with_help`、`correct_independently`、`retained_later`，并保存题目、回答和提示来源。
这些是观察等级，不能自动折算成一个宣称客观的“掌握百分比”。

日记以家庭为主体组织，人物/知识点是可筛选实体。长期事实按有效时间版本化：
“现在不喜欢恐龙了”保留前后变化与证据，不简单覆盖到无法解释过去回答。
有矛盾时保留来源、标为待澄清；自动提取置信度不是用户确认。

## 6. 持久后台队列与一致性

复用现有本地 `memory_jobs`、worker 监督和前台优先策略，扩展为有版本的持久作业。
新输入持续到来时合并相邻待处理片段，不为每个 token 启动一次模型；也不等到午夜
才处理全天内容。片段关闭、空闲窗口、明确“记住这个”和用户请求回顾都可以触发整理。

1. 同一 SQLite 事务写入原始来源和 outbox/job；job 指定来源 ID、修订、输入截止序号、
   提取器版本、输出 schema 版本及目的地策略版本。
2. worker 领取带租期的任务，生成不可变输入快照；推理不占用数据库事务或前台 turn 锁。
3. 提交前复查来源仍存在、版本未变、策略仍允许。被更正/删除的输入使结果失效，不能硬写旧结论。
4. 事务提交派生记录、其完整来源关系和后续索引 outbox 后，才推进该整理器的水位。
   幂等键包含来源范围/修订及处理器版本；重复投递不能生成两份事件或重复学习记录。
5. Graphiti 写入在独立索引任务中执行，以稳定映射 ID 和修订核对结果，成功后标记该投影水位。
   SQLite 与图数据库之间没有假设存在跨库原子事务；超时需先查已写状态再重试。
6. 进程崩溃后恢复未完成/租期到期任务，失败采用有界重试；前台语音到来时停止继续调度
   重型后台推理。模型已在推理时能否抢占以实际 backend 能力为准，不能只改 UI 为“已暂停”。

原始序号、整理水位、图索引水位、日记摘要覆盖范围分别记录。后补昨天的事件不会因为
“日期已经总结过”而被漏掉。日记或图暂时不可用时，前台仍可读取 SQLite 中被允许的
最近原文和已提交记忆，界面展示整理进度而非把整段家庭会话判为失败。

## 7. Graphiti 复用边界

候选基线为 Graphiti **v0.31.2**，版本与适配假设见
[开源比较与来源](../../research/household-memory-open-source-2026-11-16.md)。拟定映射：

| 家庭模型 | Graphiti 投影 |
| --- | --- |
| `household_id` | 由可信服务端推导的 `group_id` |
| `daily_conversation_id` | 一个 Saga；`daily_conversation_id` 与 Saga UUID 映射留在 SQLite |
| 有界 episode | `EpisodicNode`；使用发生时间，保存原始来源桥接与版本 |
| 人物、话题、物件、计划、知识点 | 类型化实体及带时间的关系；人物和话题跨日复用 |
| 检索结果 | 返回匹配关系、有效时间和 source IDs，经本地授权检查后送入前台 |

`group_id` 是分区，不是权限系统。图中仍可能同时存在不同可见性的来源；**派生物的
可见性不能比其来源更宽**。整段混有受限文字时先分割或使用允许的本地处理路径，
不能先将全文交给云端抽取后才过滤输出。优先在索引中保留策略/来源关联，召回时
再次检查当前有效性；删除或策略撤销后还须处理已经注入的 OpenCode 上下文。

Graphiti 的 Saga 增量总结适合作为简短知识概览，其默认提示词不是“当天做了什么”的
日记或学习观察格式。原始 episode、领域产物和检索图各负其责；不把全天原文作为一个
超大 episode，也不反复总结摘要替代原文。图数据库损坏或升级时可从 SQLite 的有效来源重建。

优先将 `graphiti-core` 放进 bot-server 管理的本地 sidecar；不把参考 MCP 服务的
内存队列当成产品持久调度。前台 OpenCode 通过受控检索/回忆工具使用它，不能任意
清空图、改家庭命名空间或读声纹模板。图抽取模型、中文 embedding、FalkorDB 或
FalkorDB Lite 的 Mac 打包和资源占用仍待 HC-09 验证；“本机托管”不等于默认模型调用离线。

## 8. 长对话、检索与 compact

OpenCode 继续承担前台 agent；同一家庭当日的前台输入串行送入其工作 session。
后台打印/检索/制图任务不长期占住这个 session 的全局输入门锁；有独立任务或子工作
session 时，完成摘要和真实产物链接回填家庭记录。

上下文由稳定角色与策略、当前任务、近期原始互动、compact 摘要及按需检索组成。
compact 控制推理上下文大小，后台记忆整理形成可查的长期知识，原始记录负责证据。
三者有各自版本和生命周期。compact 本身不删除家庭源记录，不把“整理过”当作遗忘。

动态召回排序或身份标注变化不能无理由销毁当日会话；实际撤销了已注入内容的权限、
删除了来源或更换了隔离范围时，仍必须清理/重建受影响的 OpenCode 上下文。
服务重启或上游 session 无法恢复时，从有效近期原文、任务状态和有来源的摘要恢复，
不可只依赖丢失后无法重放的实时事件流。实现细节属于 HC-04。

## 9. 更正、删除与迁移

**更正**产生新 revision，标出替代关系和影响范围，重算相关日记、学习观察、图关系、
检索索引和上下文。身份标注改动只影响引用该说话片段的派生物，不能把同日所有人的
记忆一并改名。资产版本和已发生的任务回执保持可审计，原始输出不会被伪装成修正后的输出。

**删除/忘记**先将来源或事实置为不可召回并记录最小删除墓碑，再撤销受影响的后台任务、
图投影和上下文；可删除的正文与媒体清理完成后保留必要的 ID/版本抑制信息，不保留已删除
正文副本。来源被删除时，仍有独立合法证据支持的事实可以保留并重算来源集合；
“忘掉这件事”则按明确语义撤销该事实及其派生物，不能仅删一个引文。
墓碑随所针对的来源生命周期管理，防止队列、重建或摘要改写重新导入已删除内容。

**原文到期清理与显式遗忘不同。** 原文归档 TTL、原始媒体和独立长期记忆使用各自的
留存策略。只有长期记忆策略本来允许保留的事实与最小证据摘录，才可在原文归档到期后
继续存在；其来源标注为 `source_expired`，不能提供完整原文/音频回放，也不能伪称还持有
原文供重新核验。最小证据摘录同样受权限、留存和遗忘规则约束，不是绕过删除的副本。
没有独立保留依据的派生物随来源清理。用户明确要求“忘掉这件事”或撤销使用权限时，
按其范围处理全部受影响事实、摘录、摘要、索引与上下文，不能借另一条 TTL 继续使用。

“删除人物档案”需在界面明确包含登记模板、人物资料、人物相关记忆或整段家庭对话中的
哪些范围。删除一个人不能级联删除其他成员的整天共享记录；需要逐来源/关系删改，
未被删除的共同事件仍可保留。既有 `delete_profile` 的个人 conversation 级联语义
只适用于旧模型，不能直接复制到家庭日记录上。

迁移分步实施：

1. 增加家庭、日记录、来源/修订和兼容映射表，保留旧 profile ID 与原 conversation ID。
2. 旧记录按已知时区/发生时间映射；信息缺失时标记历史导入，不假造说话者、原文或日期。
3. 旧个人记忆变成人物相关实体记录，同时保留原来的可见性和 `allow_cloud`；
   家庭共享化不能自动扩大权限。旧手工记忆无逐字来源时保留 `legacy_note` 来源类型。
4. 新旧读取适配并行，迁移幂等、有版本、可恢复；在完整提交前不删除旧表或改写旧数据。
5. 将文字、原始音频、图片/视频缓存、衍生记忆的留存分开配置。长周期文字档案不再受
   旧的 24 条限制；具体期限可调，继承旧安装已明确关闭的留存选择，界面显示实际生效策略。

## 10. 交付与验收证据

HC-02 先交付原始档案和迁移；HC-09 证明 Graphiti 的实际模型/数据库组合可用；
HC-10 再接后台整理与可撤销检索；HC-11 提供家庭时间线、人物筛选和声纹结果标注。
详细依赖以[实施计划](implementation-plan.md) 为准。

- 爸爸、孩子、妈妈轮流参与同一话题，仍在同一家庭日记录；未知/重叠语音不误归属。
- ASR 成功但生成失败/取消后，输入来源仍可查；只存“生成成功”与“实际播出”各自真实状态。
- 跨午夜任务、应用重启、迟到转写和迟到身份标注不会丢事件、重复任务或重放答复。
- 同一作业重复投递、写图后崩溃、身份修订与删除并发时，派生结果可解释且幂等。
