# 联调与验收｜板载麦克风到小呆屏幕

对应[开发计划](README.md)与[接口规格](protocol.md)。测试地点为运行 Bot Server 的 Mac 和同一局域网中的 ESP32-S31-Korvo-1 V1.1。麦克风与 LCD 是首版验收必需硬件，喇叭留待声音阶段。

先在 Mac 上启动正式 App，用 `dns-sd -B _espbot-brain._tcp local.` 浏览，再用
`dns-sd -L "<实例名称>" _espbot-brain._tcp local.` 查询主机名和端口。用配对 CA
验证该端口的 TLS 证书，缺少设备凭据的 WebSocket 升级预期收到 HTTP 401。
实板用同一个镜像、同一套凭据连两次，中间只更换 Mac 的监听端口并重启 App。
两次都要在串口看到新公布的端口和认证完成，并在 Mac 查到对应已连接的设备。
测试换端口、重连及服务重启时直接观察已烧录固件即可。

### 2026-11-12 接入实测

| 测试 | 观察结果 |
| --- | --- |
| Mac 单独验证发现和认证 | 正式 App 公布了系统分配的 `60984`。本机客户端按 Bonjour 结果连接，用配对 CA 验证 TLS，缺少设备凭据的请求收到预期的 HTTP 401。 |
| Mac 网关与图文测试 | Rust 的 `brain::gateway::tests`、`brain::display::tests` 共 8 项在本机通过，覆盖认证、静默协商、中文截断、图片分块及回合隔离、图片来源及图表数据依据。均可离板运行。 |
| 固件状态机的本机执行 | Mac Clang 直接编译并运行现有的 `test_runtime_near_face.c`、正式 runtime 和 attention manager，使用测试总线及 ESP-IDF 的 POSIX FreeRTOS 头文件。触摸后监听、收到 Server 确认后转入思考、本地停止等断言通过。 |
| 正式 App 生成静态图片 | 在 Mac 通过正式 App 内 worker 的 `display_image` 入口处理测试照片，得到 400×240、8301 字节的 JPEG。用观察表中的红盆 7、蓝盆 11 生成 480×272、7015 字节的 JPEG，解码后两根柱子的实色高度分别为 93 和 149 像素。本项验证到 Mac 生成的像素。 |
| 乐鑫官方 TCP 对照 | SDK v6.1 的 IPv4 TCP Client 向配套 Python Server 发送 `Message from ESP32`。当前 LAN 的直接路径上，板端记录到握手和后续报文的来源 IP 不一致。让测试板经当前 DHCP 网关发往同一 Mac 后，连续收到三次完整的 `OK: Message from ESP32`。 |
| 正式固件首次连接 | S31 用原有配对通过 Bonjour 找到 `60984`，串口报告认证完成。Mac 同时看到已建立的 TCP 连接。 |
| 正式固件持续运行时重连 | 同一个串口记录中，小呆在开机后 30.7 秒于 `7443` 完成认证，230.9 秒检测到连接断开，257.4 秒发现新端口 `61940`，258.0 秒重新认证。仅将 Mac 服务恢复到 `7443` 后，板子在 301.5 秒再次认证。全程板端只有一次开机，无需更新镜像、凭据或手工修改 Mac 路由。 |

上表记录空闲设备的接入。实际语音、运行时故障、USB 显示帧及声音输出按下方 B、S 用例记录。

## 2. 本机先定位哪一段出错

| 顺序 | 操作 | 通过标准 |
| --- | --- | --- |
| L01　构建与握手 | 在 Mac 构建现有前端、Rust 和 S31 固件。用临时设备凭据先连本机网关，再检查实板配对。另测错误凭据 | 正确凭据得到 `welcome`，错误凭据被拒。新设备、新 Server 明确确认 `audio=false`。记录构建产物版本 |
| L02　绕过麦克风 | 用 `assistant.text` 或受控的转写输入驱动同一任务处理代码。依次给出直接问答、读表、工具失败、等待授权、取消的测试事件。另在澄清期间模拟上下文已撤销 | 能逐项定位为输入、工具、结果整形或显示问题。失败/拒绝不会显示“完成”。取消后迟到的消息不更新视图。上下文撤销后再次询问所指对象，不沿用旧参数 |
| L03　静默与兼容 | 本机替代 ASR/OpenCode/TTS，给 TTS 加调用计数。测试新对新、旧设备对新 Server、新设备对旧 Server，另测 Mac 主动发起的原有回合 | 新设备静默轮 TTS 调用为 0 且无下行音轨。旧设备仍走原响应。新设备遇旧 Server 给出更新提示且不上行。Mac 主动输入保持其选定输出 |
| L04　资源与边界 | 用样本 JPEG 和图表检查画像参数、字节数和摘要。注入重复块、丢块、坏摘要、伪造尺寸、过期或跨设备句柄。检查 383 字节边界的中文、含引号/换行的长卡片 | 同一偏移重试最多一次。不接受跨轮/设备资源、坏图或损坏字符。每个序列化消息 ≤6144 字节。文字结论可单独显示。无效图片不触发第二次任务 |
| L05　工具结果 | 用当前 OpenCode 的成功/失败事件样本验证调用关联和去重。相邻两轮返回同名文件。给宿主一条只声称“已保存/已取图”的模型回答，再给真实工具结果 | 完成依据属于相应回合，有真实产物才可登记。缺证据时不得显示“已保存”或凭任意路径出图。工具已经产生副作用或结果未知时不自动回退重做 |
| L06　图片处理 | 用旋转 EXIF 照片、超限图片、损坏图片和等高、全零、缺单位的数据测 Mac 准备流程。在固件上可先注入已知合格资源 | 照片方向正确，中文标签清晰。等高/全零说明相等，缺数据时显示具体原因。过大或坏图时仍可读到文字。模拟算通过的项目仅记为本机通过 |


```sh

cargo test --locked --offline --manifest-path server/bot-server/src-tauri/Cargo.toml brain::plain_audio::tests
```

Mac App 打包及运行依[Mac 接入指南](../../mac-bot-server.md)。实板按[ESP-IDF 本机说明](../../esp-idf-development.md)选择实际端口和应用镜像，刷写与监视分开。以上用例均在本机执行。实际 ASR 和模型路线调用安排在下节的实板验收。协议边界、重复事件与错误注入可用本机替身重复。

## 3. 实板必验清单

| 编号 | 人怎么操作 | 验收人应看到什么 |
| --- | --- | --- |
| B01　激活与收音 | 待机时在设备旁说同一句话。随后轻触、等“请说”，直接说“三盒，每盒四颗，一共多少？” | 待机时无上行语音、无任务。触摸后 Mac 转写能保留两个数和语义。实体屏显示“12 颗”。同一轮有 `audio.commit`、结果和文字回执 |
| B02　静默连续提问 | 接 B01，在等待下一句时再说“那五盒呢？”随后按停止 | 新回合沿用该对话并显示“20 颗”。两轮合计 TTS 调用 0、下行音频字节 0、设备进入 speaking 次数 0。停止后回到待机 |
| B03　实际解题并绘图 | 口述“读观察表，哪盆高，高多少？画给我看。”分别用 A、B 两套数据执行。第二次可换种说法 | 每轮有可关联的成功读取及实际数据。两次现场各对上盆名、差值、单位、两柱标签和相对高度。Mac 与实体 LCD 显示同一轮结论。分别收到文字、图片回执 |
| B04　取回实际照片 | 说“给我看看观察资料里的叶片照片”。换成第二张同名照片，重新触发一次 | 两次屏幕分别看得见 L-07、L-08 和对应叶片，方向正确。板端核验的摘要等于 Mac 为该轮输出的 JPEG 摘要，旧照片没有再次显示 |
| B05　歧义与空输入 | 新会话中有两种资料时说“把那个给我看”，待追问后答“叶片照片”。另起一轮保持安静。本机补测 ASR 明确返回空串 | 歧义轮先给可回答的澄清问题，无副作用。补充后执行一次，显示对的照片。静音按当前无语音时限结束，空转写不调用 OpenCode，用户能再次尝试 |
| B06　有副作用的任务 | 将测试中的写文件操作设为现有的逐次确认。说“把比较结果写到观察小结”。分别批准、拒绝，在待批时按设备停止 | 批准时指定文件可读回且与本轮数据相符。拒绝时文件无变化、屏幕显示被拒。停止后迟到的批准无效。记录成功调用数及实际文件内容，结束后恢复原有工具设置 |
| B07　服务故障 | 在对应阶段用本机受控开关分别模拟 ASR 不可用、Mac 正忙、模型不可用、图片损坏/过期。再在实板拉图中途断开连接 | 错误原因在设备可读。图片单独失败时保留文字或图注，Mac 区分未确认与绘制失败。连接恢复后可用新任务取得结果，不会上传上一轮录音 |
| B08　停止、断网与迟到 | 在收音、等模型、等批准、拉图中分别按停止。另在写操作已开始后断网。恢复连接并开启不同任务，注入旧事件 | 停止立即中止本机上传和旧视图更新。新会话不会出现旧字幕、图片或权限提示。写入结果未知时提示检查，不自动重复执行。实际文件与调用次数可核对 |
| B09　设备显示与资源 | 看一次长中文、步骤及满尺寸 JPEG。连续做 10 次展示/返回/换轮，交替图片与纯文字，可用受控结果减少模型调用 | 实体 LCD 可读、可返回/停止。在上一帧和至少 60 秒后的 USB 帧中均能看到同一完整结果，收音等待自行结束；点关闭后图文收起，下一份有效结果可替换旧图。无重启、分配失败、残影或卡死。收回媒体引用后，记录内外堆、最大连续块的变化，查清持续下降 |
| B10　回执与隔离 | 让 Mac 收到请求但暂缓设备绘制，再只放行文字，最后才放行图片。在另一轮前撤销测试凭据 | Mac 依次可区分“已完成/显示未确认”“文字已绘制”“图片已绘制”。旧令牌不能下载图片或标记新轮已显示。撤销后旧连接失效。操作前留有重新配对方式 |

B01–B04 都经过板载麦克风、本地 ASR、已配置模型与实板显示驱动。Mac 朗读时必须走扬声器到板载麦克风的声学路径；用正式 App 的 USB 实际屏幕帧核对文字和像素，记录所用声源。B03/B04 还需在同一回合核对实际资料读取。手指触摸、LCD 背光和实际光学观感可另行记录。B05–B10 可在本机注入指定故障。

## 4. 时间、证据与交付判定

- **板端时间。** 用同一单调时钟记录触摸、可收音、收音结束、commit、文字绘制、图片绘制和停止生效。计算“说完 → 文字可读”“文字 → 图片可见”“按停止 → 本机生效”。注明是否包含静音判停时间。
- **Mac 分段。** 同一回合记录接收帧数、本地转写、启用时的说话人识别、记忆检索、OpenCode/工具、等待人工批准、准备图片及发送耗时。独立记录模型路线与回退。两端通过回合号关联，各自计算耗时。不直接相减两台机器的时间戳。
- **样本与目标。** 简单问答先测冷启动 1 次、热启动 5 次，报告实际成功次数、中位数和范围。首版调优参考目标为正常局域网下 commit 到受理 ≤1 秒、热启动简单问答说完到文字可读中位数 ≤12 秒、已有文字到合格小图显示 ≤3 秒。超目标时记录慢在哪一段。历史约 40 秒是一次提交到开始播放的观察，不能充当静默流程的基线。
- **正确性条件。** B01–B04 逐项通过，拒绝/取消后的意外执行数、跨轮旧图数、静默回合的 TTS 调用数和下行音频字节数均为零。B05–B10 分别记录结论。有失败或缺设备的项保留其状态。M4 完成以所有必验项通过为准。速度目标单列，便于有数据后调整。
