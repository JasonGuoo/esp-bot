# 小呆语音任务与 Server 图文反馈｜开发规格

目标设备为 ESP32-S31-Korvo-1 V1.1，服务端为 Mac M4 Pro 上的 Rust/Tauri Bot Server。2026-11-12 已在正式 App 和实板上验证 M0 的 Bonjour 发现、WSS 设备认证与换端口自动重连。语音、任务和屏显按[验收表](acceptance.md)分别记录。

**首版要跑通一次真人交办的任务。** 用户点一下小呆，说“看看观察表，哪盆豆苗高，高多少？画给我看。”Mac 转写语音，OpenCode 读取本轮的观察表并作答。小呆在自己的 800×480 屏幕上显示比较结论和与数据相符的图。再说“给我看看叶片照片”，屏幕能显示 Server 取得的实际图片。喇叭到货前，全程使用麦克风输入和视觉反馈。

| 开发顺序 | 本阶段交付 | 可以进入下一阶段的证据 |
| --- | --- | --- |
| M0　复现接入环境 | Mac App、已配对的 S31、可重复的观察表和图片样本 | WSS 设备认证成功。记录版本、地址配置、基线内存。用临时凭据可以在本机重复握手 |
| M1　真人语音 → 屏幕文字 | 明确触摸、麦克风采集、本地 ASR、OpenCode 回答、中文文字反馈，关闭本轮 TTS | 一句真人提问能在实体 LCD 上读到正确答案。下一句能接续。该轮 TTS 调用和下行音频字节均为零 |
| M2　语音 → 实际任务 | 依据自然语言选择现有工具，关联参数、工具执行结果、澄清、拒绝与取消 | 改变只有工具可以读到的数据后，答案随之改变。Mac 有同一轮工具成功的记录。拒绝授权时屏幕给出实际结果 |
| M3　文字 + 图片、示意图 | Mac 准备图片和数据图，固件接收、解码并呈现。Mac 可查看同轮结果及送达状态 | 一张实际照片和一张由观察表算出的图均在实体屏上可辨认。图片失败时文字仍可读 |
| M4　联合验收 | 同一固件和 App 组合完成多轮、断网、迟到回复、资源压力和耗时测量 | 本机与实板用例逐项留证，明确已通过、失败和未测项目 |
| 后续　声音输出 | 开启本地 TTS 和板端播放，安装喇叭后测实际听感、停止和回声 | 单独记录声学结果，首版 M0–M4 可先交付 |

工程接口、消息样例、限额和兼容策略见[接口规格](protocol.md)。可照着操作的测试数据、步骤、通过标准和记录模板见[联调与验收](acceptance.md)。

## 1. 从哪一步开始

| 环节 | 当前依据 | 这次需要补的工作 |
| --- | --- | --- |
| 设备与 Mac | 11 月 8 日实板已通过 USB 配置 Wi-Fi 并建立认证 WSS。11 月 12 日已在同一次开机中通过 Bonjour 重新发现两个端口并完成认证。明确激活后，单独的局域网 TCP 通道传 PCM 并做逐帧认证 | 实测在一次活跃语音或图片任务中断线后，旧任务能否正确结束，新任务能否独立完成 |
| 语音和回复 | 真人口述“三盒，每盒四颗”后，在实体屏看到“12 颗”。Mac 朗读复测中，仅唤醒一次，直接追问“五盒呢”，USB 屏幕帧显示“20 颗”。两句属于同一个设备对话和 OpenCode 会话 | 补测简单问答的冷、热启动分布，以及待批或执行中的停止 |
| 执行任务 | 已用实板口述读表和取图，并核对工具产物与 USB 画面。面对“显示那个”，小呆先问照片还是观察表，用户口头选定后才查找照片。安静输入回到待机，OpenCode 新请求为零 | 验证有副作用的任务，包括在 Mac 批准写文件、拒绝和设备中途停止，再核对文件内容及实际执行次数 |
| 静默反馈 | Mac 设备页按轮记录实际 TTS 调用、回复 PCM 字节和处理耗时。实板上两轮连续算术都记录为 0 次、0 字节。明确停止后 USB 帧回到待机脸 | 安装喇叭后，另行验收实际出声、中途停止和回声 |
| 图文和设备界面 | Mac 已实现图片来源校验、图表数据检查和分块读取。固件已包含图片摘要校验、JPEG 解码、LVGL 结果视图和绘制回执。本机用例通过 | 实板 USB 已核对两张有不同标记的叶片照片，以及改表后从蓝盆高 4 厘米变为红盆高 5 厘米的柱状图。待测图片失败后的文字显示与资源压力 |

历史验证以[实板与 Server 整合记录](../../server-integration-2026-11-08.md)和[板卡记录](../../board-bringup-2026-11-06.md)为准。现行接口以[Mac Brain v3](../../../shared/mac-brain-v3.md)为准。

## 2. 用户看到的行为

1. **说出需求。** 用户触摸设备进入对话。第一次真正可以收音上行时显示“请说”，例如“读一下豆苗观察表，告诉我差几厘米”。只有本地 runtime 授权、WSS 已认证、音频通道已就绪时才开始传本轮音频。离线时就地提示连接状态。专用“小呆小呆”模型仍待提供，本次用触摸即可走正式入口。
2. **确认听懂。** 说完一句后，设备显示处理状态。ASR 产出有效文字后可以短暂显示“听到：……”并保留停止入口。空转写提示再说一次。若“把那个给我看”找不到所指对象，小呆提出一个能用下一句回答的问题。普通问答和只读操作按已有工具权限直接进行。
3. **看到任务进度。** 数据查找、需要 Mac 上的家长确认、正在准备图片，各自有短提示。操作权限沿用当前 OpenCode 配置。设备发起请求不会更改家长选项。需要批准时，Mac 显示原有的目标、操作和允许/拒绝控件。
4. **读到结果。** 纯文字先用字幕显示核心结论。带步骤或图片时打开结果视图，优先显示结论，下面显示步骤或图片及图注。内容过长可在本机视图滚动或翻页，精简时提供“完整内容在 Mac”提示。800×480 屏幕上正文 30 px，设置 22 px。图表标签 26 px、数值 30 px。点“关闭”收起当前结果，点“停止”结束会话并收起结果。阅读和滚动都不触发收音。
5. **接着问或结束。** 视觉回复完成后进入等待下一句。新一轮沿用同一对话上下文，使用新的设备回合号。读图和收音各自计时。已绘制的结果没有阅读倒计时，追问收音到期、处理进度更新时仍可继续看。无有效结果的追问会结束收音，仍保留上次答案。下一次成功的答案替换旧结果；关闭、停止或打开设置会收起它。夜间或暗处沿用屏幕电源策略。设备只接收当前回合的媒体，迟到的旧结果不能弹出。

用户确认首版需要在小呆屏幕显示 **Server 返回的静态图片和示意图**。首版每轮可带一张。图片来源可先用工作区内经工具实际取得的样本，联网来源按当前媒体域名配置接入。视频、摄像头理解和通用 AI 绘画都需要各自的数据来源与执行能力，可独立扩展。

## 3. 任务如何由 Server 解决

| 口述示例 | Mac 应采取的动作 | 完成依据 |
| --- | --- | --- |
| “三盒，每盒四颗，一共多少？” | 本地转写，交给当前 OpenCode 路线回答 | 转写保留“三、四、盒”的含义，屏显示 12 颗。普通问答允许直接回答 |
| “读观察表，两盆差多少？把结果画出来。” | 在既有权限下读指定表，提取盆名、数值和单位，比较后交给图形渲染器 | 成功的读工具结果可归到该轮，数字和单位与源文件相符，文字与两根柱子的标签及相对高度一致 |
| “显示观察资料里的叶片照片。” | 根据当前任务定位实际图片，Server 校验并转换为设备支持的格式 | 图注对应实际文件，板端显示该图片的辨识特征。只有文件名或 URL 时继续报告获取状态 |
| “帮我查一下，豆苗的观察日记该记什么？给我三个步骤。” | 在已开启联网查询时沿用现有搜索工具，从实际取得的资料整理答案 | 板上能读到步骤，Mac 可打开本次实际取得的来源。外部服务不可用时说明原因。联网用例可在本地读表任务通过后追加 |
| “把比较结果写成观察小结。” | 按当前 `edit` 权限更新指定的测试工作区文件 | 工具成功且文件可读回，再回复已保存。拒绝、失败或执行结果未知时返回对应状态 |
| “把那个给我看。” | 上下文能唯一确定时采用它，存在多个候选则问“要看叶片照片，还是刚才的比较图？” | 用户补充后执行一次。工具授权需要在 Mac 处理，口头回答只能补充任务参数 |

语音命令沿用自然语言任务入口。复用当前 RMA Qwen3-ASR 或配置的 Whisper、现有 OpenCode v2.2.5 harness、Qwen Coding Plan → GLM Coding Plan → DeepSeek Flash 路线及已配置的工具。一次转写发起一个任务。模型负责理解目的、补齐必要参数并选择工具，Rust 负责校验实际工具结果和允许反馈的内容。首版用表格的真实内容和可读回的文件验证执行效果，避免仅凭模型回一句“做好了”判成功。

## 4. 开发分工和依赖

| 里程碑 | 负责模块与改动 | 依赖或风险 |
| --- | --- | --- |
| M0 | `brain/gateway.rs`、`brain/plain_audio.rs` 和 USB 配网工具沿用已有配对。准备临时 Mac 工作区、观察表和图片，记录网关在线、ASR 后端与工具策略 | 局域网允许 mDNS 和 TCP，服务端保持已配对的 TLS 身份。构建需可用的 Xcode 命令行工具，测试目录内使用虚构数据 |
| M1 | 网关协商静默输出，将选项传入 `Brain::turn`。固件 `brain_secure.c` 验证协商后才提交音频。沿用 `bot_runtime` 对字幕、完成、取消和下一轮的仲裁 | 当前只支持单一活动 AI 回合。Mac 忙、无语音、ASR 失败、认证失效时把可操作的原因送回屏幕 |
| M2 | `harness/turn.rs` 复用 OpenCode 的调用、成功、失败、权限和取消事件。`brain/mod.rs` 收集同轮结果。在 Mac 设备页展示本轮任务的状态与结果，复用现有卡片渲染和家长授权入口 | 设备回合当前不会自动出现在 Mac 主动发起的对话 UI。通过本地受信任的回合事件/快照展示，避免为了重现结果再运行一次模型 |
| M3a | Mac 侧从本轮实际工具结果登记图片，使用已依赖的 Pillow 转码。为数据图提供带标签、数值、单位的有限模板，与文字共用同一份数值 | 图像处理与 ASR、家长审批、控制连接可分别取消。在 Mac 上验证图片身份、尺寸和失败时的文字降级 |
| M3b | 固件 `brain_link` 负责图片传输，解码任务处理有界缓冲。`bot_runtime` 决定是否仍可显示。`app_main` 在 LVGL 所属上下文调用 `face` 结果视图 | 可先给设备注入已知 Server 测试图片验证渲染，再接 M3a 的实际产物。最终用实板麦克风、实际工具和 USB 屏幕回传核验 |
| M4 | Mac 和实板使用同一组样本，检查实际 LCD、任务副作用、取消、恢复、耗时和堆内存。测试结果分别记录，失败可定位到具体一段 | 使用本机和实板，无 GitHub CI。音频输出保持延期，喇叭到货后复用同一组口述任务 |

**技术取舍。** 推荐在已认证的 v3 WSS 上按需分块拉取一张小图，优先复用现有连接、JPEG 依赖和 LVGL。相比只在 Mac 展图，这多出固件接收与显示工作，但可以验收用户手里的小呆。Mac 单独展图适合作为 M3a 的调试节点。另开认证 HTTPS 媒体下载适合较大文件或视频，需增加端点、鉴权和第二条 TLS 连接的内存测试，待实际传输需求超出小图范围时再选择。
