## 界面结构

固定侧栏分为“日常使用”和“服务管理”。每页都有标题、用途说明和独立内容区。
对话服务启停固定在侧栏底部；“停止当前任务”固定在页头，与停止服务分开。
成员选择只出现在对话和家庭页面。模型密钥有独立入口，不需要打开高级 JSON。

模型页左边是按调用顺序排列的路线，右边是当前所选路线的密钥和设置。
记忆页以列表和搜索为中心，新增 / 编辑在同一个模态窗口完成。
证书、Worker、完整 JSON、来源与到期时间等次要字段默认折叠。
表单校验遇到折叠区域里的无效字段时，会展开该区域。

导航只保存页面标识，不保存身份、对话、密钥或媒体。
切页会关闭正在采集的麦克风 / 摄像头，清空未提交密钥；离开设备页清除一次性 token。
普通设置草稿在切页和状态刷新时保留。其他页面存在未保存设置时，不会静默覆盖。

## 设置如何保存

常用表单先读取最新 `brain.json`，只修改该表单负责的字段，再由现有后端校验、保存和重载。
没有改变的 provider 参数、路线请求体、模型预算和本地路径会保留。
密钥继续通过独立 Keychain API 保存，不进入 `brain.json`。
保存配置或密钥后，需要明确启动服务；不会因此自动发送模型请求。
本机重新打包后的 App 可能需要 macOS 再次批准钥匙串读取。启动时明确提示系统授权，
读取超过 60 秒会返回可重试的提示并释放操作锁；不会删除密钥或继续在后台启动服务。

完整 JSON 保留在运行设置的高级区域。它有未保存修改时，其他表单会提示先处理草稿。
手动重新读取 / 重载需要确认放弃未保存内容；不会自动覆盖编辑中的文本。

## 2026-11-06 设备连接记录

当时实板固件仍依赖 LAN v1 的发现和诊断通道，因此默认启用该组件并复用稳定服务器 ID。
设备页通过 composition root 注入的只读快照显示连接，Brain 不接管设备本地行为。
原型 Chat、Provider、手动 face 命令和原始 Events 页面没有恢复。

WSS v3 是另一条安全媒体链路。页面会区分未启用、等待服务启动和网关已启动，
不会把诊断在线或证书配置完成当成端到端语音已经可用。
