## 已写入的修改

| Review 项 | 本轮源码行为 |
| --- | --- |
| 4.1 控制台误取消设备对话 | `assistant.cancel` 明确区分 `turn`、`device_session`、`all`。空参数不再表示全部取消；普通换人、新对话、关闭页面只取消控制台自己的轮次，没有轮次则跳过。显式停止、服务停止、模型卸载与记忆/身份撤销保留必要的全局取消。 |
| 4.1 设备取消原因 | 网关先发送携带原 token 和原因码的 `session.cancelled`，再发送取消响应和音频事件，避免通用失败响应先准备下一 token。固件显示停止、记忆更新、服务停止或会话结束的提示。 |
| 5.2 状态事件过期 | 音频/相机/显示健康、唤醒状态、链路与时钟策略不使用 2 秒边沿租约；仍拒绝未来时间和同类倒序状态。唤醒等瞬时事件继续检查短时效。应用定期重读音频和相机状态，补回队列溢出丢失的变化。 |
| 5.1、4.3 LAN v1 | 固件在 cJSON 前检查最多 8 层括号，正确跳过字符串与转义，拒绝内嵌 NUL。新增 `CONFIG_ESPBOT_LAN_DIAGNOSTICS`，默认不启动旧连接；WSS 和 USB 不依赖它。Mac 旧诊断服务限制 4 个已升级连接、32 条新设备记录，并拒绝同 ID 顶替在线连接。 |
| 5.3 溢出故障恢复 | 播放进度、试听及声音设置改为普通队列事件；关键事件与容量独立的 Stop 保留。仅队列溢出故障可在队列排空后由本地 Stop/有意触摸清除，恢复到被动状态；恢复触摸本身不启动会话。显式硬件故障和 token 耗尽不会被此路径自动清除。 |
| 5.3 AFE 恢复 | 沿用音频 owner 的官方 AFE 重置实现；自动快速重试用尽后，在无活动会话/试听时每 30 秒请求一次慢重试。缺少模型或 AFE 对象不会伪装成恢复成功。 |
| 5.4 VAD 配对 | 音频采集 worker 保存 START 的原 token，在权限撤回、播放抑制、AFE 重置/失败、读失败、固定命令消费及退出时补发 END，避免静默遗留 `utterance_active`。 |
| 5.5 提交边界 | 本地传输提交前发出 `TURN_SUBMITTED`，runtime 进入 `SUBMITTED`，关闭同 token 的 PCM、起音缓存和固定指令；其后迟到的 START/缓存溢出不能换掉已提交回合。只有 Mac 的处理回执进入 THINKING。 |
| 5.6 运行时阻塞 | 运行时主题应用使用 5 ms 有限显示锁，初始化也不再无限等待。新增低优先级 preferences worker，复用现有 NVS API；一槽覆盖队列携带完整偏好快照与分项 revision，避免声音、主题、相机方向互相覆盖。相机仍在保存成功后才应用方向。 |
| 7.1 权限卡片 | 按 session/request ID 保留 DOM，不在每次轮询时重建；失效卡片暂留并禁用，避免下一个批准按钮移到指针下。确认框显示目标、参数和请求 ID，点击后再次核对仍为同一请求。 |
| 7.2–7.5、7.8 | 状态刷新忙时排队补刷一次；采集权限错误仅按采集点 DOMException 类型翻译；登记/识别有独立操作代数；独立设置表单可逐个保存且保留其他草稿；隐藏窗口只停止采集/播放，保留样本和音频草稿。 |
| 7.6–7.7 USB | IPC 在 blocking worker 中执行；锁内只复制变化的帧和新事件，锁外序列化，普通轮询不重复发送旧崩溃日志。页面隐藏时放慢轮询且不传图。操作结果与连接状态分行，导出路径不会被下一次状态刷新覆盖。 |
| 7.9、7.11 | production CSP 移除开发服务器来源，开发来源只放 `devCsp`；事件 capability 缩小到 listen/unlisten；错误消息使用 alert/assertive。其他列表的完整焦点恢复和 IPC 类型生成尚未实施。 |
| 8.1 诊断日志 | `~/小呆 Server/runtime/logs/server.jsonl`，目录 0700、文件 0600，主文件和两个备份各约 1 MiB；有界队列在后台写入。记录事件种类、错误码、阶段和耗时，不记录转写、回答、图片、密钥或原始子进程 stderr。Worker 的受控元数据可保留，OpenCode 自由文本仅识别少量固定系统错误码，其余只计数。 |
| 8.2 路由 | 首次输出/工具执行前的 provider 5xx 或已识别连接失败允许备用路线，默认冷却 45 秒。保留原有 `observed_output` 与 `prove_no_output` 双重禁止重放条件；超时、损坏协议或执行结果不确定时不盲目重试。 |
| 6.2 依赖 | 取消忽略并保留本机现有 `firmware/dependencies.lock`（ESP32-S31）；没有重新解析、升级依赖或修改 lock 内容。 |
| 5.9 部分小项 | 唤醒阈值应用失败不会保留旧的扬声器静音/音量；起音 PSRAM 缓存分配失败只降级缓存，保留本地唤醒；本地时区不再依赖夜间开关；为 runtime、采集、播放、vision 和离线应答加入低频栈水位元数据。 |

普通配置保存现在只保存。选择 **运行设置 → 重载配置** 才停止旧服务并加载新值，随后手动启动；保存或撤销 Keychain 密钥仍会停止旧进程。尚未保存的其他表单不会被一次保存重填覆盖。

## 复用依据与边界

- 显示锁语义来自项目现有官方 `esp_lvgl_port/src/lvgl9/esp_lvgl_port.c`：0 表示无限等待；未替换 LVGL/BSP。
- 偏好保存复用现有 `bot_platform_save_*` 与 ESP-IDF NVS；工作交接使用项目已有 FreeRTOS 一槽 `xQueueOverwrite` 模式。
- AFE 恢复复用 `bot_audio_retry_afe`、ESP-SR reset API；没有新增识别器、第二个麦克风 owner 或服务端行为控制器。
- 日志使用现有 Rust std/Tokio，不新增日志框架依赖。Tauri CSP 与事件权限沿用本机安装版本的官方 schema。
- `plain_tcp_v1` 保持用户已选择的媒体策略。分区表、配对、NVS 数据布局、模型分区、相机镜像默认值和模型顺序均未迁移。

## 尚未实施及后续本机/实板检查点

Review 是分阶段计划，不能在缺少测量时把全部建议当作已确认缺陷。本轮没有做以下结构性改动：字体/104 条音频迁到数据分区、OTA/rollback/core-dump 分区、AEAD 媒体协议、按句 TTS/文字先到、大文件状态机拆分、删除历史服务器/完整移除 LAN v1、Rust IPC 类型生成，以及未深读模块的专门审查。

相机到屏幕的符号、镜像默认值、330/350 ms 视觉时效、采集线程词表重建和全屏重绘仍需测量；这轮没有据静态推测改变已校准方向或放宽时效。

后续用户决定恢复验证时，先使用真实本机工具链检查 C/Rust/TypeScript 集成，再单独验收启动音频状态、提交后继续说话、原 token 的 VAD END、溢出恢复、快速修改多项偏好、权限卡片过期及新旧网关取消顺序。核对新增任务的内部 RAM、栈水位、应用镜像余量和日志隐私。新增故障字幕的中文字形和声音页异步保存提示尚未做 LVGL 渲染检查。分区/资产迁移需保留原 model/NVS 备份及独立升级方案。
