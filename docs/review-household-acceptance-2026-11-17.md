# 11 月 17 日语音、记忆与 Graphiti 专项验收

本次在用户要求下使用本机、ESP32-S31 实板、真实模型及云端对话测试，测试输入均为合成文字、Mac 合成语音或公开语料。以下是这次实际运行的结果，不代表所有家庭陪伴功能或长期声学表现通过。打印按用户要求暂不测试，没有触发 GitHub CI。

## 已运行

- **实板对话**：Mac 扬声器向实板麦克风播放中文合成语音，普通句子和单独“小呆”均未触发；完整“小呆小呆”触发，设备完成本地应答并录制用户问题。真实本地 Qwen3-ASR、OpenCode 2.2.5 / GLM 云端模型和 Mac TTS 完成回复，两段设备语音都分别有开始和硬件完成回执，末段完成后进入追问等待。样本量不足以估算唤醒、识别或播放质量。
- **停止播放**：首次在播放中发送 USB 本地 stop，实板停止但控制连接断开，Mac 未收到硬件取消回执。修复服务端媒体连接终止与控制连接的竞态并安装新构建后重测，设备报告音频取消、回到空闲且保持认证连接；Mac 对对应段记录了 `cancelled`，未记录 `audio_completed`。此项为本地停止测试，不是 AEC 声学打断。
- **声纹**：隔离 Python 环境使用 SpeechBrain ECAPA-TDNN 和 [LibriSpeech](https://www.openslr.org/12) 两位真实说话者的公开录音，各用三段注册并用未参与注册的独立音频测试：两人分别以余弦分数 0.839、0.817 命中自身，未注册者及撤销注册后的样本返回 unknown。阈值 0.7，候选不授予私人记忆权限。实际 ASR 和声纹嵌入也通过各自受管 worker 并行完成。该样本不能推断家庭成员或儿童声纹准确率。
- **多人分段与重叠**：用户授权后，在独立 Python 环境通过项目 worker 实际运行固定版本 pyannote Community-1。使用两名真实说话者的公开录音合成 24 秒交替和重叠样本，输出识别出两个说话者，也标出了重叠片段；被标为重叠的片段未生成声纹候选。部分边界和片段较保守，不能据此认定分段精度或真实中文家庭多人表现已达标；模型未安装到正式配置。
- **新接入的喇叭**：Mac 合成语音说完整唤醒词后，实板通过外接喇叭播放本地应答，设备报告播放开始和完成；用户确认听到了「听见你的呼唤啦，先说吧」，且声音清楚。本项不等于播放响度校准或声学打断验证。
- **接喇叭后的真实对话**：启用设备语音回答，以 Mac 合成语音提问「请分成两小段：先说苹果的英语单词，再按顺序拼出字母」。实板完成唤醒与收音，本地 ASR 识别出该句，GLM 云端模型正确回答 `apple` 及字母顺序；两段回答各有设备播放开始和完成回执，末段完成后进入追问等待。测试结束恢复语音回答关闭、设备音量 30 和 Mac 原输出音量；两段回答的外接喇叭听感未另请用户确认。
- **Server 控制音量**：新的已签名 Mac App 和仅刷写 factory 应用的 S31 固件在认证 WSS 连接下实测：从 30 调到 19、静音和取消静音，Server 先显示等待再收到已应用状态，板端音频设置版本分别完成且返回 `ESP_OK`。设备重启后仍为 19；之后恢复 30、未静音。本地设置页打开时 Server 控件禁用，关闭后恢复。断线时界面禁用控制；不把回执单独当作声压测量。最终固件大小 `0x7f4530`，factory 分区仅剩 `0xbad0` 字节。
- **人脸**：隔离环境使用固定版本 OpenCV YuNet/SFace 和公开的两人照片，真实执行三张注册样本、另一张同人的独立照片匹配、不同人拒绝、无脸图和多人图拒绝，以及撤销后的识别。注册的三张图片来自同一原图的不同分辨率，不代表家庭场景的注册或识别准确率；测试未使用或注册家庭成员的照片。
- **记忆对回答的作用**：使用独立 SQLite、真实本地 MLX Qwen3-4B 和独立 OpenCode 会话，写入虚构家庭信息，重建模型会话后问答仍正确引用该信息；再删除家庭来源并新建会话，模型回答不知道。另以模拟的前一日来源测试后台提取与跨日会话回答，回答包含对应偏好；这不是实机跨午夜测试，也不能保证模型永不虚构。
- **Graphiti**：使用独立 Python 环境的 `graphiti-core[falkordb]==0.31.2`、临时本机 FalkorDB、真实本地 Qwen3-4B 和中文 BGE embedding，运行真实索引写入、搜索、家庭隔离、错误家庭删除、删除后重建和共用关系的单来源删除。还实际运行 SQLite 来源 → MLX 后台提取 → Graphiti 后台投影 → 来源权限核验的召回链，删除来源后核验召回为空；经控制台同一接口纠正来源后，旧图结果立即被拦截，后台重建后召回新事实及新 revision。另设定普通 SQLite 上下文过短而不包含目标事实，以独立的前一日来源和新对话提问，冷启动 Graphiti 检索后本地模型正确回答且未触发 SQLite 回退；热检索的一次独立测量为 12 ms，不是性能基准。Neo4j、用户正式数据和云端 embedding 没有参与本项测试。
- **构建**：初次本机锁定离线依赖的 Rust 测试 73 项通过、1 项忽略；增加音量控制后为 75 项通过、1 项忽略，认证 WSS 协议和设备运行时测试也通过。TypeScript/Vite、Tauri release 和 S31 ESP-IDF 构建成功。本机开发签名的 App 经 `codesign --verify --deep --strict` 验证后安装并重启，原 App 和三个 SQLite 库已先在本机验收目录备份；该构建不是公证发行包。

## 发现与修复

1. 干净 Graphiti 环境缺少上游运行时直接导入的 `httpx`，已在可选依赖清单中明确声明。
2. Graphiti 0.31.2 把 `add_episode(uuid=...)` 当作读取已有节点；旧适配器先删后直接传 UUID 会失败。现在先写入持久预分配的源节点，再调用上游 API。
3. 上游 FalkorDB 会按 group 选择独立图；旧适配器的建图、查询和删除范围不一致。现在按数据库名与家庭 ID 派生隔离图名，并将适配器签名升级为 v2 以触发受控重建。已有旧实验图或外部备份须自行管理，不能宣称重建会清除其他图。
4. 真实小模型最初对明确偏好返回空数组，后台因此完成但没有记忆。调整输入结构说明后，真实 MLX 推理产生带原文和 revision 的事实，并由后台写入；无已知主体的 `self_reported` 在服务端降为 `uncertain`。
5. 测试中本地模型在遗忘后曾编造暗号，也曾把纯文字答案标成必须配图。补充模型指令后，各自重测通过；这种提示只能降低错误，不能保证模型输出。
6. 本地 stop 期间音频 TCP 先于控制回执关闭可能导致 WSS 断开。现在暂停该 PCM 流、保留控制连接等待硬件终态或超时；实板重测已收到取消回执。

## 尚未通过或仍待验收

- **AEC / 声学打断失败**：独立开启硬件参考 AEC 和 barge-in 的试验镜像实际启动了 AEC 管线，但启动阶段发生 panic 并重启，尚未进入可靠的声学测试。关闭 USB 预览后再次复现：`Load access fault` 的 PC 经试验镜像 ELF 解析到 ESP-DL `resize_nn_simd_helper_uyvy2bgr888_qint8`，调用链位于摄像头人脸检测的图像预处理；此位置本身不能证明是 AEC、并发或内存的哪一处造成。两次测试只刷写 factory 应用，恢复镜像为 11 月 16 日默认固件（SHA-256 `5df57907e4ddb5be9b254c89e061fd4f0140e33761976265ac55924811d0dc58`），esptool 写后哈希通过；刷写没有覆盖 NVS、模型及数据分区。测试曾通过设置暂时启用语音回复并恢复原值，这可能产生正常的 NVS 设置写入。
- **图文回复后摄像头重开失败**：这次使用 USB 预览运行上述图文语音对话后，进入并退出设置，DVP 备用帧反复报告 `no mem`，摄像头未能自动恢复。重启设备后相机重新出帧并运行推理；重启是临时恢复，不是根因修复。尚未证明与新增音量控制有关，也未验证关闭 USB 预览时是否复现。
- **恢复连接有延迟**：第二次恢复默认固件后，设备连上 Wi-Fi 且摄像头运行，但连续观察约两分钟未重新认证 Mac；重启 Mac 对话服务后设备重新连接。该次连接恢复不应记作自动重连通过。
- **正式配置仍未开启家庭记忆或 Graphiti**：本次检查时正式家庭 SQLite 的 `history_enabled=0`、`allow_cloud=0`，Graphiti 配置关闭，声纹样本和家庭派生记忆均为零。上述记忆、声纹和 Graphiti 测试使用隔离数据与配置，未擅自开启用户的隐私设置，也未用公开或合成声音注册家庭成员。因此当前正式设备不能据这些隔离结果宣称已记住真实家庭信息、识别家庭成员或使用 Graphiti。
- 实际家庭多人交替和重叠、真实中文说话人声纹、Neo4j、长期运行、实机跨午夜、所有异常恢复及打印均未完成验收。
