# 小呆 UI / UX / responsiveness review — 2026-11-18

Scope: static source review of the S31 firmware (`face`, `bot_runtime`, `bot_responses`,
`attention`, `brain_link`, `firmware/main`) and the Mac bot-server (console front end, `brain/`,
`memory/`, `xiaodai-core`, local TTS worker). The findings are read against the latency figures in
[review-live-turns-2026-11-18.md](review-live-turns-2026-11-18.md),
[review-turn-feedback-2026-11-18.md](review-turn-feedback-2026-11-18.md) and
[review-xiaodai-core-2026-11-18.md](review-xiaodai-core-2026-11-18.md).

This revision also incorporates the reasonable findings of the parallel
[companion experience review](review-companion-experience-2026-11-18.md). Items taken from it
are marked **[CE P0-x]**, **[CE P1-x]** or **[CE P2-x]**. Its source claims were spot-checked
against the working tree; §10 lists what was adopted, adapted or left out.

**Verification status:** review only. For this document, no build, model call, flash or physical
run was performed. All latency numbers come from the earlier acceptance records or from source
constants. The working tree contains 33 modified files on top of `702894f`. The live early
sentence, the wait acknowledgement and the 补一句 work are in that uncommitted state
**[CE P0-5]**; commit them in milestones before starting the changes below.

Yardstick: *小呆 should feel like a real, fun digital friend.* It should react instantly, have one
recognisable voice and visible emotions, know who it is talking to, surprise you a little, and
never feel like a status panel.

---

## 1. Verdict

The engineering foundation is strong:

- correct audio ownership and receipt-gated playback;
- stop, re-say and add-on (补一句) that steers or continues the current turn;
- eased eye animation and randomised idle glances;
- 104 offline wake clips and a 28-expression catalogue;
- ASR prefetch, and a model that now gives its first text in about 0.8–1.0 s.

The **felt experience** is still "careful appliance" rather than "family member". Six problems
dominate:

1. **Too slow to the first real word.** The S31 median is 4.02 s from end-of-speech to answer
   (n=6). The model accounts for about 1 s. The rest is ASR, context assembly, serial `say` TTS,
   presentation freezing and the playback handshake. Live streaming also falls back to the
   full-turn path after one or two sentences. **[CE P1-1, P1-2]**
2. **Two voices in one turn.** Wake clips use Kokoro `zf_001`; every Mac reply, including
   "听到了。", uses macOS `say` Tingting. **[CE P0-1]**
3. **A flat face during conversation.** Every core reply is `happy`, and the device only uses about
   five poses in a turn. Eyes don't move with the voice. **[CE P0-2]**
4. **It doesn't know who it is talking to or what you share.** Speaker identity never reaches the
   turn. Memory arrives as truncated raw JSON. Yesterday is forgotten. **[CE P0-3, P1-6, P1-7]**
5. **Machine-like surfaces.** The device shows status text with a seconds counter, failures are
   silent technical captions, and the Mac console opens on 11 admin-style entries. **[CE P0-4]**
6. **Thin, inconsistent personality.** The persona is mostly safety rules, with three diverging
   copies. There is one fixed acknowledgement phrase, and ordinary chat is misrouted to a 17 s tool
   path. **[CE P1-4, P1-5, P1-8]**

None of these needs an architecture change. They are all pipeline, prompt, presentation and
content work inside the existing ownership boundaries.

## 2. Responsiveness

### Measured baseline (from existing docs)

| Step | Measured |
| --- | --- |
| Commit → "听到了" first codec write (S31, n=5) | 0.79–1.98 s, median 1.07 s |
| Commit → real answer first codec write (S31, n=6) | 2.89–4.14 s, median 3.81 s |
| Device end-of-speech → real answer first write (S31, n=6) | 3.10–4.35 s, median 4.02 s |
| Core first text / first sentence / core total (Mac, t1) | 791 / 950 / 1355 ms |
| `brain_core` stage incl. 3-sentence TTS (t1) | 4512 ms |
| Tool turn on OpenCode (weather, t3) | 17.5 s |

### What already works

- Runtime step 20 ms and face tick 33 ms; the `surprised` waking pose lasts 500 ms
  ([bot_runtime/Kconfig](../firmware/components/bot_runtime/Kconfig)).
- ASR prefetch while the user pauses, with ASR and identity launched concurrently
  ([orchestration.rs](../server/bot-server/src-tauri/src/brain/orchestration.rs), lines 90–110).
- Luna-first race, with HTTP routes joining after 2 s.
- The ack after 550 ms without a first word, and the early frozen first sentence.

### Where time is lost

1. **Serial context assembly before the core starts.**
   - `household_context` and `household_recent_context` each call `purge_household_expired()`, a
     write, before reading ([household.rs](../server/bot-server/src-tauri/src/memory/household.rs),
     lines 274 and 294).
   - Graphiti recall is then awaited for up to 750 ms
     ([orchestration.rs](../server/bot-server/src-tauri/src/brain/orchestration.rs), lines 128–133).
   - **[CE P1-1]**
2. **Non-streaming, single-lane TTS.**
   - `/usr/bin/say -o file.wav` at 16 kHz builds each sentence as a whole file
     ([say_guard.py](../server/bot-server/local-models/say_guard.py), line 48).
   - The worker has one `tts` lane, which waits up to 15 s and then fails with
     `local_worker_lane_busy` ([worker.rs](../server/bot-server/src-tauri/src/brain/worker.rs),
     lines 135–137).
   - The ack, the live sentences and the final presentation all compete for that lane.
     **[CE P2-5]**
3. **Live streaming gives up early.** `LiveSpeech::ready`
   ([fast_core.rs](../server/bot-server/src-tauri/src/brain/fast_core.rs), lines 323–341) sets
   `self.output=None` for the rest of the turn in two cases:
   - The sentence doesn't end in `。！？!?.`. Endings such as `。”`, `！」`, `……` and soft splits
     fail, even though [splitter.rs](../server/xiaodai-core/src/splitter.rs) treats `CLOSERS` as
     boundaries.
   - `try_reserve` fails (line 346) on the capacity-2 completion channel
     ([gateway.rs](../server/bot-server/src-tauri/src/brain/gateway.rs), line 440).

   Stories therefore go stop-start. **[CE P1-2]**
4. **A prefix mismatch cancels the whole answer.** If the final segments differ from what already
   played, the gateway sends `session.cancelled` / `live_presentation_changed` (gateway.rs,
   lines 732–741). The answer stops part-way through. **[CE P1-3]**
5. **Misrouted chat.** `TOOL_WORDS` (fast_core.rs, line 29) matches substrings such as 任务,
   最新, 提醒, 演示, 播放 and 资料. "今天的任务好难" or "妈妈提醒我喝水" then go to OpenCode,
   where a tool turn took 17.5 s. **[CE P1-8]**
6. **Growing Luna context.** Each turn prefixes up to 6000 characters of context, including
   today's dialogue, into the *persistent* Luna thread
   ([core.rs](../server/xiaodai-core/src/core.rs), lines 475–478), which already holds that
   dialogue. Latency and cost grow through the day. **[CE P1-7]**
7. **Unknown end-of-speech window.** The device VAD silence window precedes every figure above
   and isn't measured.

### Improvements (ordered by impact ÷ effort)

1. **Keep live streaming alive** **[CE P1-2, P1-3]**
   - Accept `CLOSERS` endings in `ready`, matching `splitter.rs`.
   - Replace `try_reserve` with a bounded queue that *waits*; the gateway already serialises
     delivery with receipts.
   - On a prefix mismatch, deliver only the segments after the longest common prefix and record
     a diagnostic, instead of cancelling.
   - Add a fake-device test that streams a 6-sentence story with dialogue quotes.
2. **Take context assembly off the critical path** **[CE P1-1]**
   - Start Graphiti recall at `turn.understood`, in parallel with the SQLite reads.
   - Let the core start without Graphiti; a late result can feed a steer or the next turn.
   - Move `purge_household_expired` to a timer or the memory worker.
3. **Narrow `TOOL_WORDS`** **[CE P1-8]**
   - Drop ambiguous single words and require verb-plus-object patterns ("帮我查", "设个提醒",
     "播放…视频").
   - Otherwise rely on the core's own `〔转交〕` escalation.
   - Add the false-positive phrases above to the routing test.
4. **One fast voice with first-audio priority** (see §4) **[CE P0-1]**
   - Bench first-audio time per sentence, not only quality.
   - Give the first sentence and the ack priority over later sentences in the TTS lane, or use
     two lanes.
5. **Split the first sentence earlier.** Let only the first segment cut at the first "，" once it
   has at least 6–8 characters.
6. **Send Luna only the delta** **[CE P1-7]**
   - Send new memory hits and the current speaker candidate; the thread already has today.
   - Keep full context for the stateless HTTP routes.
7. **Adaptive end-of-speech window.** Measure the device silence window. Shorten it to about
   500–600 ms when the ASR prefetch already holds a complete question (ends in 吗/呢/？).
8. **Per-stage `TurnTimings` for every device turn** **[CE P1-1]**
   - Record ASR end, context ready, core first sentence, first TTS audio, `playback.ready` and
     first codec write.
   - Show p50/p95 in the console's existing timing presenter.
   - **Budgets:** first visual reaction < 150 ms; first sound < 700 ms; first real word < 1.5 s at
     p50 and < 2.5 s at p95, measured from end-of-speech.

## 3. The face: liveliness and emotion

### What exists

- Eased transitions (180/280/420 ms), eased blinks and smoothed gaze
  ([face.c](../firmware/components/face/face.c)).
- Idle glances every 2.6–6.0 s
  ([idle_attention.c](../firmware/components/attention/idle_attention.c)).
- Non-repeating idle expressions
  ([idle_expression.h](../firmware/components/bot_runtime/idle_expression.h)).
- 28 expressions in [eve-expressions.json](../shared/eve-expressions.json).

### Issues

1. **The reply emotion is always `happy`.**
   - [fast_core.rs](../server/bot-server/src-tauri/src/brain/fast_core.rs) passes `None` to
     `scene::normalize` (lines 328, 359, 470).
   - [scene.rs](../server/bot-server/src-tauri/src/brain/scene.rs) defaults to `happy`
     (lines 81–82), which is stamped onto every segment (fast_core.rs, lines 471–472).
   - A sad story, a scraped knee and a joke all look the same. **[CE P0-2]**
2. **About five poses during a turn.**
   [`reset_expression`](../firmware/components/bot_runtime/bot_runtime.c:67) maps listening,
   submitted, thinking, speaking and waiting to `listening`/`thinking`/`speaking`/`curious`.
3. **No audio-reactive speaking.** Nothing modulates the eyes with output level.
4. **Thinking is a static pose** during a 3–4 s wait.
5. **Touch always means "wake/converse"** (`tap_face` → intentional wake). There is no playful
   touch.

### Improvements

1. **A per-sentence emotion tag** **[CE P0-2]**
   - The core emits a one-token tag such as `〔worried〕` before each sentence.
   - Validate it against `EXPRESSION_IDS`, strip it in `LiveSpeech::ready` and in the final
     segmenter, and set it as the segment `expression`.
   - Fallback keyword table: 哈哈/太好了 → `laughing`, 疼/难过 → `worried`/`gentle`,
     哇 → `surprised`, 不知道 → `confused`.
   - The firmware keeps the segment expression during `SPEAKING` instead of the generic
     `speaking`. The runtime stays the authority and simply prefers the hint.
   - Add a unit test next to `sentences_become_segments_within_planner_limits`.
2. **Eyes that move with the voice.** Compute an RMS envelope from the playback PCM (one value per
   ~33 ms) and drive a small squash/scale and brightness pulse on the eyes. No mouth is needed.
3. **Animated thinking.**
   - Cycle micro-behaviours: look up-left, a slow scan, a squint.
   - Pop to `discovery` ("aha") when the first segment arrives.
4. **Local micro-reactions.** None of these starts a conversation, so the passive policy holds.
   - A silent double-blink and small smile when a face first appears.
   - A `surprised` flinch on a loud bang.
   - A yawn before drowsy, and a stretch on wake.
   - Rare idle easter eggs: a wink, a sneeze, watching a "bug" in the corner.
5. **Touch with personality.** `bot_runtime` decides; `face` only reports gestures. This
   reconciles with **[CE P2-4]**:
   - **Single tap = the obvious contextual action.**
     - In idle: wake.
     - While speaking: stop.
     - While thinking: 补一句.
     - The labelled 停止 / 重新说 / 补一句 buttons stay as secondary, explicit controls.
   - **Long-press or rub in idle:** `affection` and a chirp, with no session.
   - **Rapid taps:** escalate from `annoyed` to `laughing` ("别戳啦～").
   - **Swipe:** the eyes follow the finger.
6. **Variable blink timing** with occasional double blinks. Glance pace follows mood (bored is
   slower, excited is quicker).

## 4. Voice and personality

### Issues

- **Two voices** **[CE P0-1]**
  - Wake clips use Kokoro-82M `zf_001`
    ([assets-manifest.json](../firmware/components/bot_responses/assets-manifest.json)).
  - Mac replies use `say` Tingting
    ([worker.py](../server/bot-server/local-models/worker.py), lines 160 and 692).
  - A typical turn: Kokoro says "听见啦。", then Tingting says "听到了。", then Tingting answers.
  - Tingting is flat and can't carry emotion.
- **One fixed acknowledgement.** `LISTENING_ACK = "听到了。"` (fast_core.rs, line 300) fires on
  most turns, often right after a wake clip with the same meaning. **[CE P1-4]**
- **The persona is mostly rules** (fast_core.rs, line 23). It has no examples, concrete humour
  guidance or follow-up behaviour. **[CE P1-5]**
- **Three diverging personas.** **[CE P1-5]**
  - Core: whole family, 1–3 sentences.
  - OpenCode: "使用符合孩子年龄的简短中文"
    ([harness/config.rs](../server/bot-server/src-tauri/src/harness/config.rs), line 385).
  - Scene prompt: "不预设对方是孩子" (scene.rs, line 115).
- **Emoji and Markdown removal is prompt-only.** There is no sanitizer before TTS.
- **Small wake-reply pools.** There are 104 clips, but most scene pools have 8–12
  ([wake-replies.json](../shared/wake-replies.json)), so a family hears repeats within a day.

### Improvements

1. **One voice** **[CE P0-1]**
   - Add Kokoro `zf_001` (Apache-2.0, already used by `bot_responses/tools/generate_assets.py`
     through sherpa-onnx) as a `tts` backend in `worker.py`, and keep `say` as the fallback.
   - Bench first-audio-per-sentence before switching the default.
   - If Kokoro is too slow or flat, evaluate the other catalogue candidates
     ([upstream-reuse-catalog.md](upstream-reuse-catalog.md)). If the wake clips change voice,
     re-render them with the same model.
   - Map emotion tags to rate/pitch where the engine allows (excited about +8 % rate; gentle
     slower).
2. **A varied acknowledgement pool** **[CE P1-4]**
   - Pre-synthesise it in the same voice, by context: thinking "嗯……让我想想。", question "好问题！",
     story "好呀，听我讲。", late evening a softer one.
   - Never repeat within the last N turns, and skip it when a wake clip played less than ~5 s ago.
   - Before speaking, show an instant non-verbal "got it" (nod-blink and a local earcon).
3. **One shared persona module**, used by the core, OpenCode and the scene prompts **[CE P1-5]**
   - 2–3 stable traits with concrete behaviours, for example: loves 恐龙 and 星星, is bad at telling
     time, proud of small wins.
   - Rules:
     - React to feelings before facts.
     - Allow at most one playful aside per turn.
     - Vary openings; never start with 好的/当然.
     - About one turn in three ends with a short, specific question back, inside the engaged
       session only.
   - 3–4 few-shot exchanges: a joke, a comfort and a "上次你说过…" callback.
   - The condensed safety rules.
   - A version string logged per turn, so tone can be A/B tested.
4. **A defensive TTS sanitizer** that strips emoji, Markdown, URLs and unknown bracket tags before
   synthesis.
5. **Content variety**
   - At least 20 wake replies per scene.
   - Lines for being called again ("又是我～").
   - Variations by time since the last interaction.

## 5. Knowing the family: identity and memory

### Issues

- **Speaker identity never reaches the turn.**
  - `launch_identity` (orchestration.rs, line 91) runs in parallel, but its result only goes to
    the journal.
  - `speaker_person_id` is only set for the trusted console (line 87).
  - Recent dialogue is labelled with a generic `用户：` (fast_core.rs, line 265), so lines from
    several people blur together. **[CE P0-3]**
- **Memory is raw JSON and gets cut mid-record.**
  - `household_context` dumps up to 12 full JSON rows (ids, sources, evidence…), ranked only by
    term overlap (household.rs, lines 272–288).
  - `context_text` then takes `memory.chars().take(limit / 2)` (fast_core.rs, line 258), which
    can slice a row in half. **[CE P1-6]**
- **No continuity across days.** The Luna thread resets each household day, and recent context
  covers today only. **[CE P1-7]**
- **No dates** in extracted memory (`local-models/memory_extract.py`), so "我下周六生日" has no
  anchor. **[CE P2-1]**
- **One register** for children and adults. **[CE P2-2]**

### Improvements

1. **Speaker candidate in context, without waiting for it** (adapted from **[CE P0-3]**)
   - The accepted design says ordinary responses must not wait for identity, so do **not** add a
     fixed wait.
   - If the identity result is already available when the context is built, include
     `当前说话人候选：小林（声纹，未认证）`. Otherwise send it to an active Luna turn as a steer,
     or use it on the next turn.
   - Label recent-dialogue lines with the attributed speaker when known.
   - It stays non-authorising: it never unlocks private profiles, tools or print.
   - **Owner decision (2026-11-18): 小呆 may say the person's name based on a voice match.**
     Guardrails are in §12.
2. **Memory as natural-language bullets** **[CE P1-6]**
   - Format: "妈妈喜欢芒果（上周，自述）", with relative time and who said it.
   - Trim on whole items only.
   - Persona hint: "when relevant, mention one shared memory naturally; never list them."
3. **A yesterday summary:** 2–3 lines per person, injected at the first turn of a household day.
   **[CE P1-7]**
4. **Dated memories:** an optional `when` (absolute date or yearly recurrence) on `event`/`fact`
   items, plus a lookup for "events today or this week". Mention them only inside an engaged
   session. **[CE P2-1]**
5. **A guardian-set `age_band` per person,** entered in the console and never inferred. Pass it
   with the speaker candidate so the register adapts. **[CE P2-2]**

## 6. Device screen text, status and failures

### Issues

- **Engineering status on the face:** "正在发送 / 正在听懂 / 在等回答 · 4 秒 / 回答已就绪 · 3 秒"
  (stage table in [app_main.c](../firmware/main/app_main.c), around line 918). The seconds counter
  makes waits feel longer.
- **Failures are silent, technical captions.**
  - [brain_secure.c](../firmware/components/brain_link/brain_secure.c) (lines 420–431) shows
    "连接或处理失败，请在 Mac 上检查" or "请在 Mac 上配置可用模型", which are never spoken.
  - A core failure after some speech becomes `partial_spoken_answer` (fast_core.rs,
    lines 318–321), so half a story ends with an error caption.
  - `turn_timeout_ms` (60 s) also covers the serial TTS drain, so a long story with slow `say`
    can hit it after speech has started. **[CE P0-4, P2-5]**
- **Technical fallback captions:** "本地指令可用，Mac 尚未连接", "我在这里，语音对话还没接通".
- **Captions are one 30 px line with `…` truncation** (face.c, lines 113–120 and 324).
- **The sound-settings page is a long scroll** with no scroll cue
  ([face_sound_settings.c](../firmware/components/face/face_sound_settings.c)).

### Improvements

1. **In-character wait captions** with no seconds for the first ~6 s: "嗯…", "让我想想",
   "快想好了". After ~8 s, show an honest, gentle "网络有点慢，我还在等". Keep exact stages in
   USB/console diagnostics.
2. **Spoken, in-character failures** **[CE P0-4]**
   - Play a small "oops" clip pool in the same voice on `request_error`, `asr_no_speech` and
     timeouts, for example "哎呀，我脑袋卡住了，再说一遍好吗？". The existing offline wake pool is
     the starting point.
   - For `partial_spoken_answer`, end with a short spoken apology, not a failure caption.
   - Keep the technical text in the console.
   - Exclude the TTS drain from `turn_timeout_ms`, or extend the timeout once speech has started.
3. **In-character offline states:** "我的大脑（Mac）还没醒，你可以先摸摸我", shown with a sleepy or
   `worried` face. The technical reason is one tap away.
4. **Two-line captions** using the 22–26 px font, advancing with each spoken segment, so the end
   of a sentence is never cut off.
5. **Settings:** add section tabs or a scroll indicator (声音 / 唤醒 / 夜间 / 诊断), with
   diagnostics last.

## 7. Conversation flow

### Issues

- Half-duplex playback: spoken 停止/补一句 fired 0 of 3 times on the board.
- Sessions end by timeout or stop, not by a natural goodbye.
- Console actions such as naming a voice reset Luna's thread and cancel all turns
  ([rpc.rs](../server/bot-server/src-tauri/src/brain/rpc.rs), lines 66–70), so the conversation
  drops. **[CE P2-5]**

### Improvements

1. Keep touch as the reliable interrupt. Use the contextual single tap from §3, and retry spoken
   stop after the AEC acceptance.
2. Recognise closing intents ("拜拜", "好了谢谢", "不聊了") and reply with a short sign-off,
   `wink`/`sleepy`, and an immediate return to idle.
3. Make the follow-up window visible but cute: a soft glow while open, then a small yawn
   ("我先发会儿呆") as it closes. When the 60 s session times out, show a warm animation rather
   than speech. **[CE P2-3]**
4. Within an engaged session only, offer "要不要我讲下一段？" after a story. **[CE P2-3]**
5. Reset the Luna thread only on forget, correction or revocation, not on cosmetic console
   edits. **[CE P2-5]**
6. **Proactive moments** (owner decision 2026-11-18, guardrails in §12):
   - a morning hello the first time a known face appears;
   - a birthday or "today" event greeting;
   - spoken reminders the family has set;
   - a short "我想你啦" after a long absence.

## 8. Mac console (bot-server UI)

### Issues

- **11 navigation entries** ([console-layout.ts](../server/bot-server/src/console-layout.ts),
  lines 3–15), six of them under "日常使用". It reads as an admin tool.
- **The "pet" is the static app icon** with CSS rotate/drop-shadow states
  ([companion.css](../server/bot-server/src/companion.css), lines 48–51). The EVE renderer already
  exists in [preview/face-renderers.js](../preview/face-renderers.js), and the generated catalogue
  is already used by the USB debug page.
- **Text chat waits for the full result.** `assistant.turn` is awaited before anything is shown
  ([companion.ts](../server/bot-server/src/companion.ts), line 495).
- **Fixed welcome suggestions** (`renderWelcome`, line 363) and dense helper copy.

### Improvements

1. **A Friend view and a Manage view.**
   - Friend (default): a large live face, chat, and today's timeline.
   - Manage: one "管理" entry for models, local abilities, tools, devices and settings.
   - Merge 家庭成员, 补充记忆 and 谁在说话 into one "家人" page, which also hosts the age band from
     §5.
2. **Render the real face** in the console, driven by the same expression and speech-envelope
   events as the device. When a device is connected, mirror its state ("小呆在客厅，正在听").
3. **Stream console replies** segment by segment, with typing dots before the first one.
4. **Dynamic suggestions** from today's household memory and the time of day.
5. **One-line helper copy,** with the explanations moved into `?` tooltips.

### 12.1 Saying names from a voice match: approved

Voice matching remains an *observation*, not authentication. Saying a name is a social cue; it never
grants access.

- **When:** only when the speaker match passes the configured score threshold *and* the margin over
  the second candidate, and only one speaker was heard in the utterance (no overlap or unknown
  segment).
- **What:** the display name the family entered (or a guardian-chosen nickname), at most once per
  activation in a greeting or a natural callback. Never full names, and never in a private-scope
  turn unless that profile is the selected one.
- **Never:** unlocks private profiles, private memory, tools, print or any permission. Those keep
  their existing explicit checks.
- **Corrections:** "我不是小林" or similar triggers an immediate apology and stops naming for the
  activation. It also records a correction candidate on that voice segment for the console's
  "谁在说话" labelling, without silently rewriting the identity.
- **Kill switch:** a console setting, "用声音认出家人并称呼名字", default **on** following this
  decision, which can be turned off per household.
- **Update:** the persona rule "没有确定身份时不要叫出某个人的名字" and the scene text in
  `scene.rs` change to the conditional rule above.

### 12.2 Unprompted greetings and reminders: approved

This relaxes the "only explicit wake or touch starts an interaction" rule for **speaking out**. It
does **not** relax the rules for listening:

- Pre-wake audio is still never stored or uploaded.
- A proactive utterance does not open the microphone session. The person replies with the wake
  phrase or a tap.
- A short "you can answer directly" follow-up window after a proactive line is a separate,
  default-off setting, because it would upload audio without a wake.

Allowed proactive moments, each with its own toggle:

1. **Morning hello:** the first time today a confidently recognised face (or a face plus voice)
   appears in the daytime. Uses the name rules in 12.1.
2. **Dated events:** birthdays and "today" events from dated memories (§5), delivered as part of
   the morning hello or the first presence that day.
3. **Reminders:** only reminders a family member explicitly set, spoken at their time if someone
   is present; otherwise shown on screen and retried once later.
4. **Missed you:** after a long absence (for example 2+ days), one short line on the first
   presence.

Guardrails:

- `bot_runtime` remains the single authority. The Mac may *propose* a proactive line, but the
  device decides whether it is a good moment.
- **Never** during night or `NIGHT_DARK`, quiet hours, settings, an active conversation, playback
  or a task. Not while people are talking to each other (speech energy present).
- **Rate limits:** at most one unprompted line per person per few hours, and a household daily cap
  (for example 5). Never repeat the same line on the same day.
- **Volume:** a proactive line plays at or below the owner's selected volume, never louder.
- **Fallback:** if identity is uncertain, greet without a name ("早上好呀！") or stay silent.
- Proactive lines are journalled like replies, with the trigger (presence, event or reminder) as
  the source.
- A global "主动打招呼" switch, plus the per-moment toggles above.

[behavior-lifecycle.md](behavior-lifecycle.md) describes the implemented moment rules and the
speaker-only lease. The AGENTS.md product constraints summarise them.

Implementation notes for §12.2:

- **Identity:** there is no pre-wake image or audio upload, so the device has no confident identity
  before a wake. Every unprompted line is nameless, and the per-person rate limit is one "anyone"
  bucket.
- **Morning hello:** follows the first face of the day after quiet hours, until 11:00.
- **Device gap:** the device adds its own 20-minute gap between lines.
- **Reminders:** they skip the gap but count toward the cap.
- **Journal:** lines go in the additive `proactive_journal`, not in `household_turns`, so older Apps
  still read the database. Their presentation receipts are not household receipts.
