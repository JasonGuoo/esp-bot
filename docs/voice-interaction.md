# 声音设置、离线指令与 Mac 语音回答

更新：2026-11-13。适用硬件：ESP32-S31-Korvo-1 V1.1。

本次继续使用 **Mac 作为对话后端**：现有本地 ASR、TTS、OpenCode、身份和记忆模块负责自由对话，默认模型路由仍是 GLM → DeepSeek。设备独立负责完整「小呆小呆」唤醒、104 条内置应答、表情、固定控制命令及收音权限。本次没有新增脱离 Mac 的云端 Agent。

这份文档说明新增源码的行为和测试入口。主机运行时检查与设备实测分开记录；本次交付环境没有 S31 ESP-IDF 工具链、连接的开发板或 macOS Rust/Tauri 构建环境，不代表新固件及 Mac App 已完成构建、烧录或端到端声学验收。

## 1. 拉取后怎样开始

```sh
git pull --ff-only
```

固件仍按 [wake-test.md](wake-test.md) 的原有工具链、配置迁移、模型备份和构建步骤操作。第一次从未启用 `mn7_cn` 的旧版本升级，需要同一次构建生成的模型和应用；已经有匹配 ESP-SR 2.6.1 `mn7_cn` 模型的设备，本次运行时词表和设置页面随应用更新，不因增加固定指令再次训练或生成专用唤醒模型。分区地址、NVS 配对信息和用户数据不变。

Mac 端更新同一仓库的 App，避免新设备使用旧服务端的语音能力：

```sh
cd server/bot-server
npm ci
npm run tauri build
open "src-tauri/target/release/bundle/macos/ESP Bot Server.app"
```

沿用已有本机签名、Keychain、模型环境和配对配置；详见 [Mac Server 构建说明](../server/bot-server/README.md)。本次没有为升级增加 CI，也不需要重新填写已有凭据。

## 2. 设备上的「声音」页面

进入设备设置中的「声音」页面。打开设置会结束当前对话并关闭会话收音；参数操作不会替用户开启新对话。

| 设置 | 初始值与范围 | 行为 |
|---|---|---|
| 音量 | 30，范围 0–60 | 沿用现有 ES8389 输出电平上限；不是声压或听感百分比 |
| 静音 | 关闭 | 保留音量数值，关闭扬声器输出；不会关闭用于唤醒的麦克风 |
| 唤醒灵敏度 | 标准，原生门槛 0.80 | 低 / 标准 / 高对应 0.90 / 0.80 / 0.70；高档更容易触发，也可能增加误唤醒 |
| 夜间应答音量 | 30%，范围 10–100% | 在有效本地时钟且夜间策略生效时，对应答 PCM 施加一次相对增益；叠加在用户输出电平上 |
| 语音回答 | 关闭 | 开启后向 Mac 显式请求「图文 + 语音」；关闭时保持现有图文模式 |
| 试听一句 | 手动点击 | 播放一条已内置的中文语音，不需要 Mac、不打开麦克风、不创建会话；静音或音量为 0 时禁用 |
| 恢复默认 | 手动点击 | 恢复表中声音设置，保留其他 NVS 数据及配对 |

滑块在松手后提交，避免每个像素都写 Flash。`bot_platform` 用 `espbot_ui/voice_settings` 的版本化整数保存这一组设置，校验版本、保留位和范围；内容未改变时不重复提交。无法读取有效设置时使用默认值，不擦除 NVS。保存失败会提示「本次已应用，未保存；下次修改时重试」，不会在主循环中无限重写。

设备输出静音与「语音回答」是两件事：静音控制实际扬声器；语音回答开关决定是否要求 Mac 生成语音。文字模式仍可以试听内置语音。已有编译配置中的音量/门槛是底层初始参数，运行时声音偏好生效后以这里的实际设置为准。

页面诊断显示麦克风、唤醒模型、会话收音、传输就绪、防自唤醒状态、双路峰值、原生模型分数、缓存及错误计数。设置页内「对话收音关闭」是预期状态；防自唤醒进行中表示输出或尾音清理，不能当成麦克风故障。模型分数不是测得的识别准确率，峰值也不是声压级。详细处理耗时和队列高水位可看 USB 日志。

## 3. 完整唤醒后的离线固定指令

先完整说「小呆小呆」，等内置应答及扬声器尾音结束，再说以下固定短句。它们由同一个 ESP-SR MultiNet7 实例识别，不需要 Mac 在线，也不调用大模型。

| 短句 | 设备动作 |
|---|---|
| 声音大一点 | 增加 5 个输出电平单位，上限 60，同时解除静音 |
| 声音小一点 | 减少 5 个单位，下限 0 |
| 安静一点 | 静音，保留音量值 |
| 恢复声音 | 解除静音；若此前音量为 0，恢复到 30 |
| 停止 | 结束当前会话，取消输出 |
| 晚安 | 结束会话，进入手动睡眠；普通声音、人脸、白天时钟不会再次叫醒它 |
| 换成蓝色 | 应用已有「天空蓝」主题并保存 |
| 开心一点 | 显示 happy 表情 |
| 再说一遍 | 重播本次开机以来上一条成功播放的本地应答；不重放自由对话或工具动作 |

待机词表只有完整 `xiao dai xiao dai`。明确唤醒或触摸授权后才增加固定指令词表；单独「停止」「晚安」等不会从待机创建交互。这里是固定命令识别，不是自由语音理解；应按表中完整短句测试。

本地命令命中后，音频 owner 立即锁住该 token 的 PCM 输出并清空它的起音缓存，runtime 再取消旧轮次、执行动作。命令命中前若有已上传的同轮前半句，不能撤回那些字节；取消会阻止它继续成为当前远端任务。普通音量/表情命令通过字幕和表情确认，不额外捏造新的语音素材。「再说一遍」才重播既有本地素材。

当前仍没有经过验证的 AEC。扬声器播放和尾音清理期间不识别语音指令；包括「停止」在内的语音打断不保证可用。屏幕停止按钮保持有效。先测正常距离、安静环境，再测噪声和不同方向，不把默认门槛当作已完成声学标定。

## 4. 收音就绪和第一句话

`LISTENING` 表示 runtime 已授权本轮；实际就绪还分两步：音频 owner 清完旧 DMA/AFE 历史，Mac 当前轮次媒体通道连接完成。页面据此显示「正在准备收音」「正在连接 Mac，请稍等」或「我在听 / 可以继续说」。Mac 离线但本地输入可用时显示本地指令可用。

`bot_audio_set_session_ex` 允许在**本次明确授权之后、同一个 token 以内**短暂保留起音。缓存只在 RAM 中，默认约 800 ms，由 Kconfig 给出有界上限；网络就绪后按原 token 顺序释放。它不存储、上传或回放唤醒前的环境录音，不跨 token 改写标签。停止、关闭会话、新 token、播放开始和已消费的本地命令都会撤销相应缓存。

只有认证 Mac 控制链路可用、需要准备媒体传输时才启用该起音缓存。Mac 离线时保留本地固定命令识别，不为不存在的上传任务计时溢出，避免较长的离线短句被缓存时限打断。

第一轮和追问都在接受本轮 VAD START 后才允许上传 PCM。`utterance_seen` 在同 token 内记住已开始说话，即使短句先结束、网络随后才就绪，也能释放本轮授权缓存；安静等待连接不会自行提交成一轮任务。

上一轮图文或真实语音播放完成后，runtime 先分配下一轮 token 并进入 `WAITING`。此时只准备连接和本地起音窗口，不上传等待中的环境 PCM；下一次有效 VAD START 消费已经准备好的 token，不再临时换轮次、再次冲刷第一句话。缓存有限，慢连接不能保证保住任意长的抢话；真正的语音起音被覆盖时明确提示等待就绪后重说。

播放结束仍有防自唤醒的尾音窗口。在此窗口内开口可能被主动抑制，应以页面实际就绪提示为准。这次改动不宣称全双工或完全消除追问漏字。

## 5. 图文与语音共同回答

设备默认继续发送 `output.audio=false`。只有在声音设置中开启语音回答后才协商 `audio.reply.v1` 和 `output.audio=true`。Mac 调用项目已有本地 TTS，再返回文字、可选图片及 16 kHz 单声道 PCM 描述。没有添加第二个 TTS 服务、整段固件内存音频解码器或设备云端密钥。

设备成功预留现有播放队列后发送 `audio.playback.ready`，Mac 才开始发送 PCM，避免 WSS 描述和独立 TCP PCM 到达顺序不同造成丢开头。发送完毕只是媒体传输完成；真正的开始、结束、失败、取消由 `bot_audio` 的硬件事件回执给 Mac。接收有背压处理、序号/长度校验和有限超时，TTS 缺失或播放失败仍保留文字反馈，不冒充已播放成功。

`BOT_COMMAND_REPLY_PRESENT` 保留文字，实际播放结束才准备下一轮。即使极短音频先于文字事件处理完成，runtime 也会等本轮文字接纳后再换 token。只有真实硬件写入的低频进度可以延长播放期间的进展时限；网络到包不会让卡住的扬声器无限续期。媒体长度仍受服务端和固件上限约束。

图片使用独立的结果 token：预连接下一轮不会取消上一轮尚在下载的图片；真正开始新一轮、关闭结果、设置或停止会撤销旧下载权限。图片和文字的展示回执仍基于实际 LVGL 绘制与刷屏完成，不把收到数据当成已经显示。

当前 Mac TTS 是已有的整段生成路径，尚未实现按句首包播放。控制与文字仍走认证 WSS，PCM 沿用用户此前选择的局域网 TCP 加完整性校验路径；本次没有改变媒体传输策略。协议细节见 [mac-brain-v3.md](../shared/mac-brain-v3.md) 和 [设备任务协议](specs/server-voice-tasks/protocol.md)。

## 6. 建议按这个顺序做实板验收

1. **试听**：打开声音页，低音量试听；改变音量、静音、关闭设置、点击停止，确认输出及时响应。重新启动，确认设置保留且配对未丢失。
2. **唤醒与负例**：完整「小呆小呆」有应答和匹配表情；单个「小呆」、间隔较久的两个「小呆」、电视声音及自身播放不应误触发。记录失败率，不能只录一次成功。
3. **离线**：退出 Mac App，唤醒后试表中固定指令；确认不生成自由回答。说「晚安」后等白天时钟变化、走到镜头前，再主动唤醒，验证睡眠边界。
4. **图文模式**：Mac 在线，保持语音回答关闭，完成一次问答和图片任务；在图片下载中准备追问，确认原结果仍可显示。
5. **语音模式**：开启语音回答，用相同问题确认文字、表情与真实扬声器输出；检查 Mac 只有硬件回执后才记录完成。测试停止、Mac 断开、TTS 不可用和播放队列背压。
6. **追问**：分别在就绪提示前后开口，测试短词、短句、正常问句；核对缓存计数和 token。慢网络超过缓存容量应提示重说，不能把截断语音默默当成完整一句。
7. **夜间**：使用正确本地时钟和夜间策略，比较内置应答与 Mac 语音回答的相对音量。未知时间保持中性，不用开机时长猜几点。

主机验证覆盖了试听权限隔离、旧 token 拒绝、离线命令消费、手动睡眠、夜间增益传递、下一轮预授权、硬件 DONE 与文字 PRESENT 两种先后顺序，以及保留结果的图片失败反馈。这些检查用于发现运行时逻辑回归；不能替代官方库链接、ES8389 播放、模型识别率、S31 并发负载及 Mac 实际模型运行。

声音页还使用官方 LVGL 9.6.0 与项目真实 face/字体源码完成了 800×480 主机离屏渲染检查，检查了滚动布局、滑块松手提交、旧快照不拉回、静音禁用试听、恢复默认与返回导航。实际字形查询覆盖设置所需的 250 个非 ASCII 字符及 app/runtime 新提示的 108 个字符；22px 压缩位图增加 17,846 字节，30px 大位图未修改。这是主机界面验证，不是板上 LCD、触摸、NVS 或扬声器验证。

## 7. 代码入口与复用依据

| 入口 | 职责 |
|---|---|
| `firmware/components/bot_voice` | 共享设置、固定指令 ID、只读诊断 DTO；无硬件和行为权限 |
| `firmware/components/bot_audio` | 唯一音频 owner、ESP-SR 词表、设置应用、有界缓存、真实播放事件 |
| `firmware/components/bot_runtime` | 唤醒/固定指令/试听授权、轮次生命周期、文字与播放完成仲裁 |
| `firmware/main/wake_response_player.c` | 内置 ADPCM 流式解码、相对增益、可取消播放任务 |
| `firmware/components/face/face_sound_settings.c` | 声音页渲染与用户意图回调 |
| `firmware/components/bot_platform` | 版本化 NVS 设置读写 |
| `firmware/components/brain_link/brain_secure.c` | 能力协商、播放握手、媒体接收和真实硬件回执 |
| `server/bot-server/src-tauri/src/brain/gateway.rs` | 保持现有 Mac Brain/TTS，新增可选语音设备输出 |

ESP-SR 接入沿用官方 2.6.1 MultiNet 接口及已核对的小智完整自定义唤醒模式；界面沿用项目的 LVGL 9，持久化沿用 ESP-IDF NVS。详细官方文档和成熟项目证据集中在 [前一份调研](research/esp32-s31-standalone-agent-feasibility-2026-11-13.md) 与 [上游复用清单](upstream-reuse-catalog.md)，这些外部项目的能力不等于本项目已完成硬件验收。
