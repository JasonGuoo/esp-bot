# 多轮对话、停顿与打断实机记录：2026-11-19

## 环境和测量方法

- 正式 Mac App `0.2.2`，源码 `18d4990e02f9`；S31 `korvo-01` 固件 `0.2.1`，扬声器 17/60、未静音。设备和 Mac 通过已认证的 WSS 控制连接通信。
- 用 Mac 扬声器播放 Tingting 合成普通话，设备真实收音，经过本地 ASR、Luna、Mac TTS 和 S31 音频硬件。语音合成速率分别包含 125、190、260、320；这些速率是 `say` 的设置值，不是人声测试或识别准确率。部分测试音频经过动态范围压缩，播放增益仅作用于测试文件。
- 实板 USB 诊断预览保持开启。串口测试接收器本次记录 113 个无效包、85 条设备侧日志丢弃计数；不能把诊断预览当成完整的声学录音。回答内容取正式 App 的设备页面，是否开始和结束播放取服务端收到的硬件回执。
- 完整输入的 8 个后续对照样本中，从 Mac 测试音频播放程序结束到服务端收到设备回答首个硬件写入回执为 **3.65–9.74 秒，中位数 5.29 秒**。这是两个本机时间点之间的近似值，含网络回执时间和 USB 诊断负载；样本少，不是长期 P95。1 次提前断句的回答不计入这组完整输入时延。
- 测试日志、合成音频、截图和脚本保留在本机忽略目录 `firmware/.bringup/dialogue-test-20261119/`；关闭了诊断进程和测试会话。没有改动设备音量或 Mac 系统音量。

## 对话实录

以下引号中的识别和回答来自控制台，不是预先写好的预期答案。

| 场景 | 输入或操作 | 小呆实际识别与回答 |
| --- | --- | --- |
| 常速，第一次 | 「请用一句话告诉我，彩虹是什么？」 | 识别成「请用一句话告诉我：彩虹。」；回答「彩虹。」后半句丢失。 |
| 常速，第二次 | 同一句 | 识别完整；回答「彩虹是阳光穿过空气中的小水滴后，散开的七彩光带。」 |
| 快速连续追问 | 「那为什么它有不同的颜色？」 | 识别完整；回答「阳光看起来是白色，其实由许多颜色组成；水滴会把这些颜色弯折、分开，所以我们看见了彩虹。」 |
| 慢速 | 「请用一句话解释，雨是怎么形成的。」 | 识别完整；回答「太阳把水晒成水汽，水汽升到高处变冷、聚成小水滴，云里的水滴变重后就落成雨。」音频播完到回答首写约 8.7 秒。 |
| 连续对话第 1 轮 | 「地球绕着什么转？请回答一句话。」 | 「地球绕着太阳转。」从播放结束到回答首写约 8.0 秒。 |
| 连续对话第 2 轮 | 「那月亮呢，它绕着什么转？」 | 「月亮绕着地球转，也跟着地球一起绕太阳转。」约 3.7 秒。 |
| 连续对话第 3 轮 | 「那地球绕太阳一圈大概需要多久？」 | 「地球绕太阳一圈大约需要一年，也就是三百六十五天多一点。」约 7.7 秒。三轮之间没有重新唤醒。 |
| 两次较快语速 | 「请用一句话告诉我，海水为什么是咸的？」 | 两次均完整识别，均解释了盐从岩石经河流进入海洋、水蒸发后盐留下来；从播放结束到回答首写分别约 5.3 和 4.1 秒。 |

## 停顿对照

使用同一组「请告诉我」和「树叶为什么是绿色的」录音片段拼接，分别额外加入 0.35 秒和 1.5 秒静音，其他处理一致。以录音文件 `-35 dB` 阈值计算，两段之间静音约 0.55 秒和 1.70 秒；房间中的实际声学间隙可能不同。

- 较短停顿两次都完整识别并回答。一次回答为「树叶里的叶绿素吸收了一部分阳光，并反射较多绿光，所以我们看见树叶是绿色的。」
- 较长停顿第一次完整识别并回答；第二次在音频播完前就提交了「请告诉我」，回答「你想让我告诉你什么呀？」后半句没有进入这次回答。
- 早期探索中，另一组短停顿连续两次、同一句早期短停顿一次被判为 `audio_too_quiet`。早期脚本没有严格确认新一轮收音就绪，且后来调整了测试音频动态范围，不能直接将这些失败归因于停顿长短。

## 打断和续答

- **直接说话打断播报**：两次严格对照中，在设备回答音频仍在播放时播放「停一下，我想问别的」，两次均没有取消播放，也没有建立新语音回合。之后立即触屏「停止」，两次均收到音频取消回执并回到空闲。之前另有一次相同方向的尝试，也未发生语音打断。当前固件默认关闭声学 AEC 和自动语音打断，这是半双工现状，不是已支持全双工。
- **播报中触屏补话**：两次在真实回答首音开始后点击「补一句」，两次旧音频均被取消，新语音「把小兔换成小狗」被识别并有实际播放回执。一次最终回答为「小狗在山坡上发现月亮躲进了云朵后面。它敲敲云边，担心月亮迷路了。微风吹开云朵，月亮又对小狗亮起笑脸。要不要我讲下一段？」另一次也讲了小狗和月亮。两次日志均为 `context_continuation`。
- **思考中触屏补话**：三次实际触发了原回合取消，其中两次补充音频被判 `audio_too_quiet`；另一次完成并播放了新回答，日志显示 `context_continuation`。那一次的最终文本被随后新的设备事件覆盖，不能确认其具体内容，也不能把这次当作 `luna_steered` 验证。

## 其他实际现象与限制

- 一次原故事没有被听清后，在没有再发送测试合成语句的时间里，设备连续产生多次 `no_speech` 和提示，屏幕显示「我没听清，再说一遍好吗？」另一次控制台显示输入为「.」，回答「我在呢。」。设备同时多次报告附近有声音；本次没有录制环境声音，因此无法确定当时声源或是否有人说话。应复核唤醒后环境声触发、空输入过滤和失败重试的行为。
- USB 诊断打开导致设备重启后，一次 70 秒内没有恢复 WSS；Mac 当时的 Bonjour 服务只在 Docker 虚拟接口可见，Wi-Fi 接口没有看到。重启 Mac 的对话服务后，两种接口均可见，设备重新认证。尚不能仅凭本次现象断定广播消失的根因。
- 本次没有真人语音样本、真实语音回声消除验证或 GLM/DeepSeek 真实故障切换测试。声学质量、人物口音和长期统计仍需单独测试；设备闲置时的未知声音也不等于已判定为误唤醒。
