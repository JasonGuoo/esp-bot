# 小呆 Server / 设备整合记录（2026-11-08）

## 实际数据位置和已有配置

- 正式数据目录：`~/小呆 Server`；App、配置、本地模型、记忆、OpenCode 数据及
  `runtime/opencode/workspace` 工作区均放在这里。macOS 钥匙串仍负责 API Key。
- 首次迁移由 `server/bot-server/scripts/migrate_data_root.py` 使用 SQLite 快照和
  OpenCode 自带的 session export/import；只导入小呆会话，不导入其他项目。迁移后
  旧来源暂时保留以便回退，旧全局 OpenCode 数据不受新进程写入。
- 原有 RMA Qwen3-ASR 优化代码、Python 环境和权重复制到目录内；系统 Python / macOS
  运行库仍是外部依赖。浏览器 MCP 仍连接用户现有 Chrome，逐次授权政策不变。

## 慢速记忆

会话产生的用户文本可进入本地 SQLite 有界队列，后台任务使用独立的 MLX 进程和本地
`mlx-community/Qwen3-4B-Instruct-2507-4bit` 模型提取。前台回合开始会中止后台进程，
稍后重试；原始音频、照片和 embedding 不进入该队列或云模型。模型输出必须包含用户原话
中的连续原文作为依据。用户已授权相关记忆文字随问题发给当前云模型；本地专用的手工记忆
依旧遵守原有云端开关。

个人身份未确定时，个人事实先存为“身份未确定”，不会作为任意人的个人记忆召回；
界面可查看、删除或明确关联到成员。明确的家庭共享事实可以作为共享记忆使用。
自动提取仍会出错，界面标明来源并可修改或删除；这不是经过用户逐条核实的事实。
已登记的本地人脸/声纹模块仍是候选识别，阈值未校准；当前设备协议尚没有人脸图像上行，
因此不能声称机器人已能自动把面对的人或说话者与记忆可靠绑定。

## 网络与安全

板端 v3 使用固定信任的本地 CA 和设备专属 bearer token，只有本地明确触摸或完整
唤醒词建立会话，控制和文字通过认证加密连接传输；按用户要求，语音通过单独的局域网
TCP 明文传输，逐帧完整性校验不提供保密性。配对脚本只监听指定 Mac 局域网地址；
CA/服务端私钥及服务端 token 摘要在该数据目录。网关当前绑定当时的具体 Mac 局域网 IP；
IP 变化后需更新监听地址，并确保连接主机名仍能解析。设备目前未启用 Flash/NVS 加密：有实体
硬件访问能力的人可能读出设备 token，撤销或轮换后旧凭据失效。不要把这称为硬件密钥库。
蓝牙配网、专用完整唤醒词声学模型、设备图像上行和实体扬声器仍未完成。

控制台“设备连接 → 通过 USB 设置机器人 Wi-Fi”提供 2.4 GHz 网络名称和密码输入。
密码不写入 Mac 控制台配置或 USB 事件记录；它通过 USB 传到开发板并保存在设备 NVS，
优先于构建时网络配置。现有设备 NVS 未加密，具有实体访问权限的人可能读取。
配网保存与实际连网是两回事；还需等设备取得地址和网关显示在线。

## 本次验证边界

Mac 端前端与 Rust release 构建、Apple Development 签名、实际控制台启动和三个已保存
Keychain 条目的存在已验证。迁移演练及正式迁移均导入 4 个小呆 OpenCode 会话。DeepSeek
Flash 已使用一条虚构短消息实际回复；Qwen 首选端点测试遇到等待响应头超时，随后
安全回退到 GLM 并收到回复。密钥有效性不能由超时推断。当前实现只在确认原回合没有
任何部分输出、工具或 shell 操作后才尝试按顺序回退；其他不确定的失败不会被自动重放。
另外通过控制台提交了不读写文件的虚构任务，OpenCode 的 `shell` 工具状态为
`completed`，并返回约定字符串；这验证的是 Mac 控制台侧工具调用，不是实板端到端。

本地 Qwen3 记忆模型已用虚构中文和无事实消息做推理，后台队列实际清空；SQLite 本机
测试覆盖身份未确定、原话校验、遗忘后迟到任务不能恢复、旧版数据库迁移。迁移后的
RMA Qwen-ASR 用 Mac 合成的中文音频实际转写成功。未运行 CI。

ESP32-S31 固件已本机编译、只写入应用分区并校验；最终安全配置经 USB 收到设备明确
确认。刷新证书后用 Espressif 工具复位，观察到空闲状态、递增的采集计数和屏幕/相机
USB 预览；这不等于摄像头识别身份或实体扬声器通过。网关本机集成测试使用临时凭据
验证了可信 TLS、认证设备建会话和未认证连接的 HTTP 401；运行中的实际网关也验证了
可信证书链及未认证拒绝。

加入 USB 配网后的固件已再次编译并写入应用分区，设备启动及屏幕/相机预览正常；
通过 USB 发送空的无效配网数据时，实板返回拒绝，没有覆盖现有配置。

用户通过 USB 配置可用的 2.4 GHz 网络后，开发板返回保存确认。使用 Espressif 工具
复位后，设备取得 Wi-Fi 地址，并与本机网关建立真实的已认证 WSS v3 连接；控制台显示
`korvo-01` 安全在线，设备日志多次显示 `secure_link=1`。此前网关连接初期出现
TLS 内存不足和重试，诊断 WebSocket 也出现任务创建失败，仍需检验内存优化及重连表现。
这次握手不等同于完整语音或自主工具任务已从实板端到端通过：明确激活后的语音采集、
Mac ASR/大模型回复和可用的声音输出仍待实测。

随后将 LAN 诊断任务栈和任务队列优先放入 PSRAM，本机重建并仅更新应用分区，烧录
哈希校验通过。新固件启动约 30 秒内重新出现 `secure_link=1`，控制台再次显示一台
设备安全在线，运行至 190 秒时仍保持连接；一次 USB 预览采样显示内部空闲 13819
字节、最大连续块 5888 字节。
此前同类采样曾低至 11479/1024 字节，这不是严格受控的性能对照，也不能保证所有负载
下不会内存不足。早期实板诊断通道的 WebSocket 升级出现超时；后续运行中控制台已
实际显示该设备的诊断连接在线。

按用户选择改为明文语音后，本机合成帧测试通过了 TCP 收发、帧完整性拒绝及提交时
跨连接的帧数等待。实板能建立语音 TCP 连接，但初次发送在约 1.5 秒后堵塞，尚未完成
语音回合。进一步探测发现，本机与开发板之间 ICMP 负载 312 字节可以往返，316 字节及
以上的样本全部丢失；到路由器的 1200 字节样本正常。这是本次环境的观测，并未证明
故障一定发生在路由器或开发板的哪一层。音频连接临时使用较小 TCP 分段的尝试仍然
失败，已撤回。现按乐鑫排障建议关闭 Wi-Fi 聚合、省电，并将可迁移的 Wi-Fi/lwIP
分配优先放入 PSRAM；下列结果是本次实板测试，不代表长期稳定性已经验收。

上述无线调整已在本机编译并只写入应用分区，烧录哈希校验通过。更新后，64、512、1200
字节 ICMP 负载各 4 次均收到回复；完整语音测试后复测也各为 4/4。设备已改用与证书
SAN 匹配的 Mac 局域网 IP 重新配对，避开本次出现的 mDNS 解析失败。Mac 的 IP 变化后
仍需更新网关和设备配置。

由 Mac 扬声器播放“请回答连接成功”。开发板在明确手动唤醒后建立明文 TCP 音频通道，
连续提交 1090 个帧；Mac 上复用 RMA 的 Qwen-ASR 正确转写测试句，OpenCode
调用 GLM 生成“连接成功啦！我是小呆，很高兴见到你，有什么想问的吗？”。设备先后报告
`thinking`、`speaking`、`waiting`，说明本地 TTS 和板端播放队列完成了本次流程。测试后
已主动停止会话，设备回到 `idle`；设备运行至约 328 秒时认证和诊断连接均在线。
本次约 17 秒录音包含测试前等待，
从提交到播放开始约 40 秒；这不是稳定延迟基准。由于尚未确认实体扬声器连接，不能把
播放流程完成等同于实际听到声音，也不能以这次回合证明长期无线稳定性或身份识别准确性。

外部 USB 配对会更换设备凭据；App 必须完全退出后重新打开以载入更新。若配对后串口没有
恢复，可用 Espressif 工具复位开发板，不能把未收到串口画面误判为无线连接成功。
